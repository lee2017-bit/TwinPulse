## AD2 automatic recorded session implementation

The existing App displays **Automatic sensor mapping**. A user selects a saved input session and optionally a previously completed map, then presses Start once. No individual frame, point correspondence, fixed route or old pose is supplied. The built Web calls authenticated `/v1/product/automatic-demo/start`; the owned App worker consumes the AD1 recorded observation adapter and calls the same pure `AutomaticMapping.consume` runner used by the closed-loop tests. Opening, listing, polling and reopening never contact a robot.

The product endpoint currently accepts **verified recorded input only**. This is a real product path, not mocked UI responses, but it is not the AD4 live robot or Isaac mission adapter. Live normalized observations can enter the same core runner; automatic physical acquisition, qualification, control and 3D rendering still need their later product integration.

New input initializes a session-local origin rather than inventing a world location. Revisits use a different, already completed source/map with project, nominal model, raw hash, boot and receipt ordering checks. The source and map are reverified before derived output is saved. Global search runs only at initialization or loss; normal tracking uses odom prediction and a bounded local endpoint search. Flat costs, poor angular coverage, excessive innovation, source changes and odom jumps reject or invalidate the binding. Three spatially separated supports, not three almost identical scans, are required for TRACKING_CANDIDATE.

Pause, seek, manual reposition and cancellation change the owned epoch and immediately clear the displayed estimate. Resume reconstructs causal state from the original input rather than carrying a previous pose. A superseded worker cannot publish an old result or error over the new epoch. Terminal sessions do not resume automatically. Status includes elapsed time, source sequence and precise failure stage; asynchronous failures appear in an English error dialog. Completion freezes the elapsed timer and refreshes the available maps. Offline processing remains available during an Isaac startup error, and cancellation remains available while project switching is pending.

Maps are stored exclusively under project-scoped `artifacts/automatic-mapping`, separately from the unchanged v1/v2 ProjectRecord serialization. Saved corrected/odom grids, keyframes, transitions, source failures, nominal model revision and observation health retain their hashes and provenance. Reopening returns **no current pose and no motion authority**. Historical processing candidates remain historical evidence, not a restored live robot position.

## AD2 map semantics and resource limits

Each 10 cm cell carries its acquisition stamp, source revision and occupied/free observation counts. Only valid finite rays contribute observed free space. Missing returns and unobserved cells remain unknown; conflicting evidence is not cleared into convenient free space. The occupied/free/unknown separation follows the [ROS OccupancyGrid message contract](https://raw.githubusercontent.com/ros2/common_interfaces/humble/nav_msgs/msg/OccupancyGrid.msg); the implementation stores sparse evidence rows rather than claiming to publish that message.

The worker bounds pending scans to 8, cells to 18,000, keyframes to 128, retained trajectory points to 512, raw input events to 65,536, source extent to ±12 m, ray range to 8 m, derived files to 4 MiB and processing to 120 seconds. The existing distance-field/global-search budgets impose a tighter practical small-room search bound. Budget failures are explicit, not truncated success. Raw inputs are immutable. Expensive derived matching is sampled every 500 ms; intervening paired scans still propagate the estimate through odom. Derived analysis skips/drops and original raw data counts are separate. UI rendering samples at most 2,000 cells; storage retains the bounded full map.

Corrected and odom-only maps are distinct. Matching happens against past evidence before current insertion. A supported revisit is labelled **FRONTEND_REVISIT_SUPPORTED_NOT_POSE_GRAPH**. There is no global pose-graph solver, retroactive keyframe deformation, calibrated SLAM result or metric physical error claim. The [Cartographer algorithm description](https://google-cartographer-ros.readthedocs.io/en/latest/algo_walkthrough.html) distinguishes local scan matching from global optimization; this code implements only a bounded frontend, not Cartographer. Diagnostic `reference_eligible` means sufficient separated/revisit evidence for another offline query, never permission to navigate.

Dynamic odom TF is cross-checked at its own declared stamp against already received odom. A disagreement over 1 mm or 0.001 rad raises ODOM_DYNAMIC_TF_CONFLICT. Missing static TF is still NOT_RECEIVED, and nominal mounting and acquisition timing remain unverified. These are evidence-consistency tolerances, not physical accuracy or new stopping criteria.

### Structural model, ambiguity and evidence separation

The expected sensor section is extracted at the **nominal** sensor height (182 mm for the preserved model), separately from photo outer geometry. Only upright static walls crossing that height are treated as structural constraints. Furniture/lower geometry is **UNKNOWN**, not a solid box down to the floor or evidence of free space. This phase does not recover furniture footprints or unseen geometry.

Contiguous endpoint windows produce bounded PCA line fragments. Their repeated support must come from separated scan origins and original sequences; gaps and varying line offsets reject fragments. The automatic search pairs nonparallel observed and nominal wall structures to generate rigid SE2 candidates. It does not scale, reflect, stretch or import a previous global robot pose. Fit error, inlier fraction, wall support and the margin over a distinct competing transform must all pass. Symmetric, insufficient, structurally mismatched and held-out-inconsistent cases have distinct non-success statuses. Reports identify the need for separated stable nonparallel wall views or an asymmetric structural constraint; the algorithm does not invent that evidence.

At most 40 views are selected automatically from the bounded AD2 keyframes. The first 60% form the fit set; one boundary view is purged and the remaining views form held-out validation. Exact source sequences and stamp intervals are stored. These views are disjoint, but share the same raw/boot odom and TF: **DISJOINT_VIEWS_SHARED_ODOM_TF_NOT_INDEPENDENT_GROUND_TRUTH**. They demonstrate model consistency, not independent physical position accuracy or calibrated acquisition timing.

Geometry evaluation fixes the candidate transform and nominal revision. A proposal may translate **at most two walls, each at most 0.20 m along its normal**. Thickness uncertainty is not edited. No dimension, rotation, global scale, height, material, furniture or object-ID change is permitted. Both intervals must support consistent wall offsets, floor/collapse checks must pass, target held-out residual must improve at least 25 mm, global held-out mean at least 1 mm, and inliers must not worsen. These are new offline geometry-proposal tests, not modified physical stop thresholds. Non-identifiable/no-improvement proposals are rejected with wall-specific reasons.

### Persistence, ownership and rollback

`AutomaticPhotoStore` stores immutable hash-bound reports and exclusive append-only apply/rollback events under `artifacts/automatic-photo-alignment/<project>`. Every event records base/head/map/job revisions, before/after objects and `goal_revalidation_required=true`. A changed base opens a separate ledger; old evidence is preserved. Competing writers cannot overwrite the same event. Hash/chain/path/project/head conflicts reject application. Originals, v1/v2 ProjectRecord hashes, photo files and existing scene-change files are unchanged.

The derived effective scene is saved and becomes input to a later automatic run. It is **not yet an Isaac stage edit or a general authoring-history merge**; AD4 must consume/display the qualified revision and revalidate targets before use. UI overlays show nominal walls, proposed/effective walls and held-out structures only after a usable candidate transform. Reopened results are historical evidence, with no current pose or restored motion authority.

Rollback is a separate authenticated explicit request. It appends a compensating event only when the requested applied head still matches; old reports remain immutable. It works after service restart and rejects tampered/cross-project/stale-head requests. A new active worker blocks rollback. Cancellation or superseded epoch during fitting cannot save/apply late output. A room/raw/model change during fitting rejects the result; failure records include the stage and safe code. A photo-stage storage failure retains a completed map checkpoint instead of claiming a full successful photo job. No automatic retries are introduced.
