# 수동 컨트롤러 — PC 구현, 실물 요청은 미완료

2026-09-27 KST. 사용자는 점검 뒤 직접 전후진·제자리 좌우 회전·라이다를 조작할 수 있는 화면을 요청했다. **이번 결과는 그 요청의 부분 구현이다. 실물 버튼을 쓸 수 있는 완료본이 아니다.** 사용자 배터리 단독 전원 ON 보고 외에 이번 새 실물 관측은 없다.

## 구현 범위

- 기존 App/경량 로봇 콘솔에 `RobotController` 화면과 인증/CSRF API를 추가했다. 기본 실물 탭은 잠김, 명시적으로 선택·확인한 PC 모의 탭만 동작한다. 별도 설치는 없다.
- 전진/후진(합성 ±0.03m/s), 제자리 좌우 회전(합성 ±0.20rad/s), 버튼/키보드 유지 입력, 해제 정지, 모의 전체 정지, 모의 라이다 시작·정지/8초 제한.
- 입력 유효기한·증가 순서·세션 소유권·단일 세션·최대2초 연속 입력·60초 세션, 독립25ms 점검 루프. 창 이탈/숨김/터치 취소/해제/닫기 처리. 통신 오류 후 자동 재개하지 않는다. 늦은 이전 세션 응답도 무시한다.
- 서버는 메모리 안에서 합성 위치/속도만 계산한다. SSH/ROS/serial/Isaac 연결을 만들지 않는다. 물리 모드를 요청하거나 정상 보고서를 가져와도 실제 제어를 허용하지 않는다.
- 브라우저 입력 취소가 실제 로봇에 전달되거나 위 시간에 실물 정지가 보장된다는 뜻이 아니다. 화면의 전체 정지도 물리 비상정지 기능이 아니다.

## 적용과 남은 개발

화면을 보려면 작업 중이 아닌 기존 점검용 콘솔을 Ctrl+C로 종료하고 저장소 루트의 `Open-Robot-Console.cmd`를 다시 연다. 단순 브라우저 새로고침으로 기존 Python 서버가 교체되지 않는다. 이번 모의 기능에는 로봇 전원·재부팅·재점검이 필요하지 않다. 기존 실행 중 서버/타 프로세스를 강제로 종료하지 않았다.

실물 완료 조건은 다음과 같다. 사용자가 설정을 더 채우는 것으로 해결되는 항목이 아니다.

1. 기존 정지 안정 관측122ms / 요구200ms 실패의 원인 진단과 새 계측 시험기. 기존 실패 기준과 소비된 일회 시험 표식은 유지한다.
2. 로봇 측 단일 소유권·fresh report/부팅/배포 identity·배터리·정지 상태에 묶인 실제 수동 제어 연결 및 로봇 측 입력 만료/종료 확인. PC 메모리 watchdog으로 대체할 수 없다.
3. 기존 bounded LiDAR 수집기를 화면 작업·중단·최종 상태와 연결. 무응답/정지 미확인 상태를 성공으로 표시하지 않는다.
4. 사용자가 현장을 보고 있는 별도 승인된 실물 시험으로 release/통신 끊김/정지 결과를 확인한 뒤 버튼 활성화. 앱 점검 통과만으로 자동 활성화하지 않는다.
