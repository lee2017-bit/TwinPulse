# DP1 saved evidence review through the local App — 2026-09-30

Robot OFF. This increment adds authenticated, read-only `GET /v1/product/robot/physical/evidence/review/<job_id>` for an exact saved 32-hex job ID. It never starts preparation, transfer, sensor, motor or SSH. The handler selects only `<controller-root>/artifacts/manual-control/<job_id>/robot-evidence`, rejects symlinked path components and calls the existing exact-byte offline inspector. It returns file/binding/raw-structure findings but no local path, raw bytes, credential or robot authority. A missing export or malformed receipt is `INCOMPLETE` with a bounded reason; a completed local receipt is re-read rather than cached, so a subsequently modified file is also `INCOMPLETE`.

Local App HTTP test: unauthenticated access rejected; valid authenticated request before export is `EVIDENCE_NOT_EXPORTED`; exact-ID and query validation reject malformed requests. A fake transport builds an OFF-mode saved bundle; App review reports `COMPLETE` while `raw_ros.status=NOT_CAPTURED` and `physical_validation=NOT_RUN_BY_THIS_TOOL`. Tampering `off.log` changes the same App review to `INCOMPLETE/HASH_OR_SIZE_MISMATCH`; corrupting `export.json` changes it to `INCOMPLETE/EVIDENCE_INSPECTION_ERROR`. No physical controller child was started. The generic offline-release source and installer required-file lists now include the inspector, its bounded diagnostics module and raw reader; this is a static inventory check, **not** a clean release build or company-PC installation.

Related no-device export/recovery/diagnostic/preparation/physical-controller/DP0 regression: **114/114 PASS** in the existing repository `.venv`. The first focused test expected HTTP 409 for a query string but the API's outer request validation returned 400; the expectation was corrected without weakening the query rejection. No network or robot operation was performed. Existing raw integrity/receipt failures and prior physical stop FAIL remain unchanged.

Limits: this route does not decode real ROS CDR on the current PC, validate message semantics/TF geometry, prove a complete actual robot transfer, measure bandwidth/disk budget, or provide a user-facing review panel. An OFF-mode file set has no ROS raw data and must not be presented as sensor evidence. The fixed local path checks do not eliminate a concurrent filesystem replacement race. The full DP1 acceptance and DP2–DP5/PC readiness remain open; live motion remains locked.

Later update: the missing user-facing panel was added to project-bound saved session history, and the API was restricted to the current project's indexed journal.
