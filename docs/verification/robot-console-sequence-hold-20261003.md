## Product changes in this increment

- Dedicated console now places operator confirmation and connection setup ahead of drive pad, stop summary and historical operation result. The old failure remains accessible in results; it is not rewritten.
- The compact Connect button is gated on either a just-completed, owned and physically verified qualification in this page or a saved passing qualification with confirmed cleanup whose boot and release match the **fresh read-only observation**. When matched, redundant package preparation and stop-test actions disappear. Otherwise only the next valid preparation action is enabled; a failed test for the same boot/release does not become a retry path. The robot still independently validates its qualification receipt on every control start. Package preparation is deployment/Motor OFF, not the read-only connection check; stop qualification is a distinct physical movement test. After reload, a changed release requires a new read-only check before a saved result can unlock the UI.
- A held manual direction now sends a stop after approximately 1.4 seconds, waits for the robot-side `RELEASING`→`READY` idle acknowledgement, and only then sends the still-held direction again. This retains the robot's 2-second hard limit and 60-second session limit; release, focus loss, Force STOP and delivery failure still halt/close. It is stop-and-resume, not smooth uninterrupted motion. Browser/transport stalls can still end the session; no timeout threshold was weakened.
- LiDAR-only controls are visible rather than buried. A new explicit **manual + LiDAR** mode uses one owned robot worker/session, not two competing port owners. With wheels disabled it starts the pinned isolated ROS driver and waits up to eight seconds for at least three scan and odom observations; the manual pad is only enabled after readiness. The same worker checks driver liveness and fresh, unique `/scan` during control, then reaps its driver, issues sensor STOP/quiet/port cleanup, ROS halt and final independent board read. Missing/early-exit/stale scan or incomplete cleanup remains a failure with specific reason. This is supervised manual collection, **not scan-based collision prevention**.
- The combined mode is now offered only if the fresh observed robot release equals the local deterministic deployable-source identity and a matching stop qualification exists. An older qualified release can still offer its existing manual control, but not the new combined mode. The console exposes an explicit package-upgrade and new-release stop-test path; neither runs automatically. After a newly owned qualification, its actual release must equal the local identity before the combined button unlocks. This prevents a seemingly enabled control button from invoking `control_scan` on a release whose worker lacks that mode. A bundle-vs-runtime-source-hash parity test checks the local identity calculation.
