# 전원이 켜진 로봇의 데이터 우선 시험 규칙

사용자 요청: 배터리/현장 시간을 먼저 사용하고, 전체 제품 완성을 기다리지 않는다.
이 규칙은 실패를 통과시키거나 이미 정의한 실물 정지 기준을 완화하지 않는다.

1. **필요 조건을 시험별로 분리한다.** 원시 센서·SSH·로그·전압·장치 재시작은
   사진 품질/전체 TF/자율주행 완성을 기다리지 않는다. 물리 이동이 없는 관측과
   명시된 저속 정지시험, 수동 주행, 자율주행은 서로 다른 판정이다.
2. **전원 ON 동안만 얻는 자료를 먼저 확보한다.** 현재 boot/release/바이너리 SHA,
   전압/명령/속도/엔코더, 원시 빔과 시각, odom/IMU/TF, 시작·종료·재시작 및
   중단/연결 종료의 원본 로그를 수집한다. 분석/모델 수정/보고서 렌더는 나중이다.
3. **실패해도 독립 가지는 계속한다.** 균일 LaserScan 거절은 native-angle raw 저장이나
   disarmed base telemetry를 막지 않는다. 결과와 실패 단계·실행 ID·SHA를 보존한다.
   같은 실패를 원인 변경 없이 배터리가 닳도록 반복하지 않는다.
4. **Torque ON은 이동 판정이 아니다.** 센서 전용은 신선한 zero command/velocity,
   전후 encoder<=2ticks·전압·same boot/release·포트 소유/복원을 확인한다.
   이 표본을 지속적인 무이동·물리 정지·주행 허가의 증거로 승격하지 않는다.
5. **배터리는 실측 전압으로 확인한다.** 기존 near-protection11.1V 이하에서는
   새 active test를 시작하지 않는다. 기존 field motion margin11.4V 미만은
   물리 이동 시험을 시작하지 않는다. 퍼센트는 추정이며 잔여 시간을 약속하지 않는다.
6. **주행 준비는 정지시험을 하기 위한 무한 선행조건이 아니다.** 기존 한정된
   stop qualification을 그 시험의 조건(현장 감시/로봇 둘레30cm 확보/전원 차단 가능,
   검증된 guard/zero-start/신선 telemetry/전압)에서 먼저 수행할 수 있다.
   전체 방 재구성·라이다 정합을 고정 정지시험의 선행조건으로 추가하지 않는다.
   다만 실제 설치 코드의 속도·시간·이동범위부터 확인하고, 임의 cmd_vel은 쓰지 않는다.
7. **수치·기준은 사전에 기록한다.** 문서0.03m/s와 현재 소스0.05m/s 불일치를 발견했다.
   실제 설치 소스/버전을 확인하기 전 0.03m/s라고 말하고 실행하지 않는다.
   이미 발급된 stop receipt가 다른 boot/release이면 재사용하지 않는다.
8. **중단·회복도 데이터다.** 수집 cancel/EOF 후 STOP·port restore·child reap와
   독립 readback을 기록한다. 실패하면 해당 장치의 새 활성화를 멈추고 상태를 먼저 읽는다.
   데이터 quiet를 실제 rotor-stop으로 대체하지 않는다.
9. **판정은 기능별로 한다.** PASS_SCOPED/FAIL/BLOCKED/NOT_RUN, 원시저장/메시지화/
   좌표정합/주행을 분리한다. CLI 보조시험은 일반 설치 App UI 인수와 구분한다.
10. **종료 전에 자료 반출을 확인한다.** 원본·클리핑 없는 raw·누락·시각·TF·표본·종료
    로그를 PC에 복사하고 SHA를 확인한다. 저장된 자료로 재현할 수 있으면
    이후 코드 수정/분석 때문에 로봇을 다시 켜 달라고 하지 않는다.
11. **실제 앱의 입력 계약과 시험 도구를 맞춘다.** 현재 앱은 입력 expiry250ms,
    갱신100ms다. 더 짧은220ms 보조시험의 실패는 별도 성적으로 보존한다.
    expiry를 앱과 일치시키는 것과 로봇의250ms 판정 기준을 늘리는 것은 다르다.
    이번 실패는 source age174.758ms/활성화104.803ms로 초기 입력의 남은75.242ms가
    소진된 기록이다. 앱과 같은조건의 재시험도 단1회 성적이며 장래 지연 보증이 아니다.
12. **준비 완료는 구체적인 기능 이름에만 붙인다.** 연결UI/로컬PC 준비/원시저장/
    정지성능/수동입력/정합/자율주행을 구분하고, 일부 PASS를 전체 준비완료라고 말하지 않는다.
13. **정지 센서시험과 짧은 구동시험을 따로 끝낸 것은 동적 통합 인수가 아니다.**
    회전·이동 중 라이다/odom/IMU 동시자료, 메시지/시간/좌표 검증, Twin 보정을
    따로 판정한다. 분할 회전 누적360도를 한 세션의 한 바퀴/지도 루프 성공으로 세지 않는다.
    원시 이동자료 수집은 전체 SLAM 완성을 기다리지 않되 현재 guard와 신선도는 유지한다.
14. **임시 메모리 자료는 보조파일까지 반출한다.** raw·CDR뿐 아니라 시각/byte offset,
    footer·단위·소스·누락·연결 계보를 PC에 저장/검증한 뒤에만 반출완료라 한다.
    23f/g/h의 tmpfs chunk파일이 후속조회에서 없었던 결함을 보존한다. 같은boot였고
    삭제 원인을 사용자 전원차단으로 단정하지 않는다. 원시자료는 보존됐지만 개별 빔 시간은 미검증이다.
15. **시험 도구의 종료도 검증한다.** 정상 close 직후 controller.close로 pending graceful
    close를 EOF로 바꾸지 않는다. 23f의 이 helper 결함을 제품 고유 결함으로 단정하지 않고,
    구동 구간 자료/정지와 실제 세션 FAILED를 별도 기록한다.

이번 최초 고정 정지시험 때 제 안내가 전방20cm였다는 절차상 차이는 삭제하지 않는다.
이후 사용자가 전후좌우30cm 확보를 명시 확인한 뒤 네 방향·해제·입력중단 시험을 진행했다.
기존2틱/200ms settling은 비교 진단이고, 설치된 supervised-stop-2.1이 실제 평가 정책이다.
이번 데이터에 맞춰 그 정책·제한·receipt를 수정하거나 구FAIL을 PASS로 바꾸지 않았다.

현재 데이터와 전시도는 [단일 보고서](../../outputs/robot-obstacle-prior-20261017/report.html)에 기록한다.
