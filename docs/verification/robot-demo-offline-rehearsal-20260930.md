## What is prebuilt versus what cannot be inferred

The source already contains a bounded raw COIN capture with fixed START/STOP and failure cleanup, strict odom/scan contracts, explicit planar binding, local collision check, one-scope mission loop, command/observation journal, and robot-local stop guard. The new rehearsal verifies their **fake/stored contracts together before power-on**, not their live integration. The currently shipped profile deliberately has `motion_enabled:false`, no autonomous-control policy and no reviewed real navigation calibration. The App likewise rejects live mission start. These are safety gates, not a missing checkbox to bypass.

Next short field window should first run one authorized no-motion collection and inspect its exact odom/TF/scan codes. The current guarded base does not start the ROS COIN driver or static TF publisher; `scan:NO_PUBLISHER` is expected until a separately reviewed driver lifecycle exists. The installed COIN ROS driver's join-before-STOP concern is still unresolved; raw capture is not a `LaserScan` substitute and data silence is not physical rotor-stop proof. User photo/model geometry do not establish room↔odom or sensor extrinsics. Without valid live same-boot observations and independently reviewed calibration, a real autonomous mission must stay locked. The offline run has nevertheless identified these blockers **before** consuming the next battery window, rather than discovering them after power-on.
