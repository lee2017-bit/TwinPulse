# 실패 후보 복원과 재검사 수정 결과

2026-10-10 · Baseline v1.0.388

이전 후보로 복원할 때 현재 실패 원인을 빈 진단으로 덮어쓰던 제품 결함을 수정했다. 실패한 수정안의 진단과 복원 후보의 재검사 결과를 따로 저장하고, 복원 후 기하·관측 배치·설정된 현재 렌더 검사를 거친다. 예산이 남으면 맞는 수정 단계로 이어지고, 재검사 실패나 예산 소진은 성공으로 처리하지 않는다.

Provider 회귀 308건, 관련 App·실행 로그 통합 회귀 203건이 통과했다. 두 suite의 겹치는 fixture 검사를 합산하지 않는다. 저장된 실제 다섯 모델 응답의 최종 재생은 5/5 회귀 통과다. **새 모델 호출, 실제 Isaac 실행, 로봇 명령은 각각 0**이며, 실제 모델의 추가 수정 성공이나 전체 데모 완료를 뜻하지 않는다.

## 원인과 제품 변경

`BudgetedPipeline`은 기하 검사가 통과한 후보를 best로 저장한다. 사진 비교가 아직 수정 필요 상태여도 best의 기하 진단에는 오류가 없다. 이후 수정안의 packing이 악화되면 기존 코드는 best로 돌아가면서 그 빈 진단을 현재 오류 위에 덮어쓰고 `UNMAPPED_COMPILER_ERROR`를 발생시켰다.

다음 경로를 기존 제품에 반영했다.

- 실패한 후보 revision·typed 진단·실패 patch는 그대로 보존한다. 복원 후보의 새 기하 검사와 관측 품질 상태는 별도 `rollback_revalidation`에 기록한다.
- 복원한 후보는 실제 compiler로 재검사한다. 기하가 통과해도 사진 비교가 수정 필요하면 같은 소비 예산 안에서 품질 수정으로 돌아간다. 아직 기하가 미완성인 후보는 재검사에서 나온 해당 기하 진단을 사용한다.
- 이전에 기하 완료였던 후보가 재검사에서 실패하거나 신뢰할 수 없는 checker 오류가 나오면 `ROLLBACK_REVALIDATION_FAILED`로 종료한다. 예전에 기하가 통과했다는 이유로 현재 실패를 무시하거나 계속 복원하지 않는다. 원래부터 미완성인 후보의 수정 가능한 기하 오류는 새 진단으로 계속 수정할 수 있다.
- 현재 렌더 정보는 복원 시 해제하고 과거 렌더 이력은 보존한다. 렌더 검사가 설정된 요청은 새 capture·critic을 거쳐야 수락된다.
- 실패한 유료 patch의 진전 결과를 한 번만 계산한다. 로컬 복원·재검사를 새 수정 호출로 세거나 같은 실패를 이중 차감하지 않는다. 성공한 최종 수정은 정체 카운터를 해소한다. 제품 기본 횟수·시간·출력·보호 조건은 변경하지 않았다.
- patch가 만든 revision과 현재 검사 revision이 같을 때만 patch의 성공 상태를 갱신한다. 복원한 이전 후보의 통과로 실패 patch를 성공으로 덮어쓰지 않는다.
- App 공개 진단에는 실패 코드, 실패/복원 revision, 복원 기하 검사, 품질 상태만 제한적으로 노출한다. 원 후보·자유 응답·인증 정보는 공개 DTO에 포함하지 않는다.

변경 경로는 `packages/twinpulse_provider/src/twinpulse_provider/budgeted_pipeline.py`와 `packages/twinpulse_app/src/twinpulse_app/product_workflow_service.py`다. 새 네트워크 fallback, 모델별 정답, 특정 사진의 치수·배치 하드코딩은 없다.

## 실제 저장 응답 재생

`scripts/replay_rollback_failures.py`는 이전 비교의 원 응답을 그대로 현재 제품에 넣는다. 시작 전에 Windows asyncio의 내부 wakeup pair만 만들고, 재생 중 socket 연결을 금지한다. 키를 읽거나 공급자 endpoint에 요청하지 않는다. 원 비교 자료는 읽기만 하고, 결과는 별도 파생 경로에 저장한다.

| 원 모델 | 기존 실패 | 수정 후 재생 확인 | 새 모델 성공 |
| --- | --- | --- | --- |
| DeepSeek V4 Pro 0813 | packing → 빈 진단/UNMAPPED | 복원 기하 통과 → 현재 품질 수정 요청 | 미검증 |
| DeepSeek V4.1 Flash | 동일 | 동일 | 미검증 |
| Kimi K3 | 동일 | 동일 | 미검증 |
| GLM 5.3 | 동일 | 동일 | 미검증 |
| GLM 5.3 Flash | 동일 | 동일 | 미검증 |

다섯 경우 모두 원 packing 진단과 실패 revision을 보존하고, 복원 revision과 다음 품질 수정 요청의 후보 revision이 일치했다. 원 응답 5/6/5/5/5개를 각각 재사용했으며 소비 수정 횟수는 원 시험의 각 2회와 같았다. 추가 응답이 필요해지는 지점에서 **`SAVED_RESPONSES_EXHAUSTED`로 중단**했다. 저장된 자료에 없는 새 답변을 만들거나 모델에 요청하지 않았다. 따라서 회귀 통과를 생성 성공으로 세지 않는다.

최종 근거는 `outputs/rollback-revalidation-20261010/r5/report.json`과 모델별 파생 checkpoint다. 원 비교 JSON·사진 1,093개 파일의 SHA가 불변이다. 별도 read-only 기존 비교 감사에서도 HTTP142개 원본·dispatch·validation·장부 연결 오류는 0이며, 원 시험의 49/70 결과와 비용 추정은 바꾸지 않았다.

## 회귀 범위와 최초 실패 기록

새 provider 반례 7건은 마지막 수정 슬롯 소진, 악화/순환 후 복원→품질 회복, 정체 중단과 원 진단 보존, 공개 로그 필터, 복원 compiler 실패 시 종료, 미완성 기하의 재수정, 복원 후 새 현재 렌더 요구를 검사한다. 새 통합 2건은 실제 다섯 응답의 무네트워크 재생과 재생 자료 소진 시 무예약·무전송 중단을 확인한다.

- 수정 전 packing 반례에서 기존 `UNMAPPED_COMPILER_ERROR`를 재현했다.
- 초기 테스트의 임시폴더 권한 오류는 정상 시험 권한으로 재실행했고, 잘못된 크기/대상/NO_CHANGE 반례를 실제 packing 경로로 정정했다. 합성 치수는 시험 데이터일 뿐 제품의 사진별 규칙이 아니다.
- 복원 checker 실패 반례에서 반복을 발견해 `ROLLBACK_REVALIDATION_FAILED` 경계를 추가했다. 그 반복 중인 이번 턴 소유 회귀 PID4572만 종료했으며, 다른 프로세스는 종료하지 않았다. 수정 후 전체 회귀가 종료·통과했다.
- 최초 통합 실행 182건은 시험 package 경로와 소유 자식의 `PYTHONPATH` 누락으로 실패했다. 이번 시험 프로세스에만 package 경로를 제공한 최종 관련 통합 203건은 통과했다. 시스템 설정은 변경하지 않았다.
- 재생 도구의 import, Windows loop guard 초기화, 보고서 저장 kind, 정렬된 semantic revision 기대값을 정정했다. r1~r4 파생 기록은 보존하고 r5를 최종 근거로 사용한다. 원 모델의 과거 실패는 수정하지 않았다.

## 남은 검증

이번 제품 결함은 오프라인 반례와 실제 원 응답 재생 범위에서 수정·검증됐다. 다음의 외부 검증은 별도다.

1. 새 모델 응답으로 복원 후 품질 수정이 실제 수락까지 도달하는지 확인한다.
2. 추천 observer와 Lightning을 일반 App 라우팅에 연결하고, 새 관측→생성→실제 현재 Isaac 렌더 비교→수정→저장/SIM을 조합으로 인수한다.
3. Ultra 공백 퇴행의 모델/decoder/schema 원인을 대조하고, 중단했던 설계 21건의 2회차를 별도 실행 승인 안에서 진행한다.

기존 실제 사진 충실도·도메인/패키지·해커톤 규정·로봇 정합/자율/Loop/안전 인수도 유지한다. 이번 요청은 오류 수정이므로 중단된 유료 비교를 자동 재개하지 않았고, 사용자 모델/키 설정과 원 장부·출력 중단 기준은 그대로다. 전체 데모는 PARTIAL이다.
