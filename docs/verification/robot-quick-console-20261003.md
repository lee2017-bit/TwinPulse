# Robot console quick-flow UI — 2026-10-03

User-reported defect: the dedicated console exposed several verbose panels, required a click for a read-only connection check, and locked the controller behind Isaac supervisor readiness even though the launcher intentionally does not start Isaac. It was unclear whether text described an observed result or a requirement. A first browser rehearsal also caught that `?robot-console=1` was rejected by the local server's query-data policy; the final launcher uses a hash marker and strips only the bootstrap secret before the request.

The `Open-Robot-Console.cmd` launcher now opens the dedicated console. After local session bootstrap it performs one PC preflight + one read-only SSH status check automatically, with no automatic retry. The compact view shows its current result, time and board/battery snapshot, a retry button and a collapsed detailed report. On a fresh successful observation the manual pad and setup appear; failure leaves them absent and shows the error. The dedicated mode does not depend on Isaac readiness. Normal App routing remains unchanged.

This does **not** auto-deploy, start LiDAR or motors, run a stop test, or authorize movement. Direction controls remain disabled until the existing current-boot/release stop qualification and manual-session checks succeed. The on-site confirmation and explicit physical operations remain separate. A board snapshot is not a live stop test.
