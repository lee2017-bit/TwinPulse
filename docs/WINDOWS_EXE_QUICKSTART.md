# TwinPulse Windows EXE

This is an unsigned Windows x64 simulation alpha candidate with an independent Electron app window. It includes the desktop host, App's Python runtime, built React interface and the reviewed ROBOTIS Burger simulation assets. Install Isaac Sim separately on a compatible Windows/GPU system; Isaac, GPU drivers and API credentials are not bundled. Physical robot controls are not available in this alpha. A separately declared read-only robot build can offer explicit connection observations; check the capability message in Robots.

1. Extract the complete ZIP. Keep `TwinPulse.exe`, `_internal`, `desktop` and the manifest together.
2. Run `Install-TwinPulse.cmd` to install per user, then `%LOCALAPPDATA%\TwinPulse\installed\Start-TwinPulse.cmd`. The same start entry follows the active installed release. Portable use of `TwinPulse.exe` is also supported. If needed, select the installed Isaac folder containing `python.bat`.
3. The independent app opens before Isaac finishes preparing. Wait for the authenticated connection indicator before using 3D commands.
4. Use New chat to create a separate conversation in the same app/address. Run the same installed Start entry to focus/reopen the existing app without another backend or Isaac instance.
5. Use **Exit TwinPulse** to stop the App and its owned Isaac engine normally. The independent window's close button requests the same normal shutdown; it is not a hide-to-tray action. Stop a simulation or response first if the app asks you to. If only the renderer crashes, the manager does not silently abandon ongoing work: use the same Start entry to reopen it. The explicit diagnostic browser mode is different; closing that browser only closes its view.

## Optional automation checks in the same app

Normal Start discards inherited testing-port settings and opens no automation port. For a test session, exit normally and use **Start-TwinPulse-Test.cmd** beside the installed Start (or the portable EXE). It starts the same package with `--automation-test`, a loopback-only port and a visible TEST MODE badge. A running session is never silently changed between normal and test modes; close it normally first. The next normal launch is debug-off.

Open **Tests → Run basic checks** while Isaac is connected and the app is idle. A bundled, version-pinned Playwright worker clicks the actual installed window: Robots, Library typing/results and Twin pane. No extra Node/Chrome installation, paid generation, network discovery or SSH is needed. Do not use the app controls during this short check. **Tests → Open check report** opens the local report and screenshots; these may contain conversation/device information, so review before sharing. Nothing is uploaded automatically. A basic PASS is not full generation, native OS input or physical robot qualification. The debugging port grants local programs broad control of this app; keep testing mode limited to the test session and never expose/forward the port. Robot preparation and motion gates remain unchanged.

API keys holds provider/model routing and editable model-specific harness instructions. Existing saved Legacy routes are not silently rewritten. Save routing explicitly to select a profile; custom/new-model instructions remain compatibility-unverified until tested. Schema, geometry checks and robot authority are not editable through a prompt profile.

Robots starts empty on a fresh installation. Search shows network service advertisements observed during that search, with a last-search time and a maximum30-second validity (shorter advertisement TTLs expire sooner). It is not a continuous power/reachability or identity check. Saved robots remain registered even when off; no response means not observed, not proven offline. Remembered Bluetooth devices/local ports are separate OS inventory, never current network search results. A robot must advertise a supported service and network discovery must be allowed; simply enabling SSH is not sufficient to appear. Register/select the intended robot explicitly and run Check PC preparation. Search does not automatically connect or change the saved endpoint. Plain SIM builds stop at local preparation. Read-only robot builds additionally offer Check connection: this explicit action runs bounded SSH health reads, existing ROS topic observations and a reviewed board-read check. It does not deploy software, start a sensor driver, collect a survey or enable a motor. Unknown hardware requires an adapter review and calibration; TwinPulse does not infer a safe motor protocol from a Bluetooth or USB name. A successful read-only result is not motion readiness.

The local address is remembered across restarts. If another program occupies that port, TwinPulse selects and remembers a bounded alternative. No public network listener or local DNS configuration is required. Provider API calls are made by the local backend over HTTPS.

Existing API-key references, conversations, scenes and incomplete work remain in `%LOCALAPPDATA%\TwinPulse\runtime`; key material remains in Windows Credential Manager. Moving the extracted package does not move or remove these user records. A different release cannot take control of a live launch from another installation: exit the old launch normally first.

## Manual updates and recovery

Exit TwinPulse normally, extract the entire next ZIP and run its `Install-TwinPulse.cmd`. Installation refuses a live launch; it does not force-stop another instance. It retains the previous executable pointer and leaves projects, original attachments, incomplete checkpoints, edits and Windows Credential Manager entries in their existing locations. Launch the same installed Start entry afterwards.

This alpha writes data epoch 1 without conversion. A release declaring an incompatible epoch is refused before switching. An interrupted same-epoch install can be rerun from the identical intact package. Do not manually reset data or edit active-release.json. Automatic rollback is limited to packages declaring the same supported epoch; arbitrary future-format downgrade is not provided. No automatic update download, forced update, telemetry upload or background paid inference is performed.

For a bug report, open Diagnostics and record App version/build ID, the affected execution ID and your actual click sequence. Export redacted diagnostics only if you want to share them, and review the file yourself. Original prompts, photos, responses and private paths are not required for a public issue. Do not upload keys or a whole runtime directory.

This unsigned candidate is not an assertion of final photo accuracy, clean-PC acceptance, physical robot readiness or public release clearance. Preserve the included Apache-2.0 LICENSE/NOTICE and component-original notices. SHA256 identifies bytes; it is not a publisher signature. Do not disable OS security to run a blocked package. See the release acceptance record for exact tests and remaining work.

A failed generation may preserve only a resume checkpoint and static preview, not an accepted saved scene. Object counts are not proof of image fidelity; dimensions without measurements remain estimated. The first alpha is for compatible-system testers, not a claim that any PC works with only an API key.
