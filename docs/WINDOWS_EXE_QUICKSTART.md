# TwinPulse Windows EXE

This one-folder package is how company PCs install TwinPulse. It already contains Python, the web UI, the desktop window, the Isaac extension and the robot assets. Only **NVIDIA Isaac Sim 6.0.1** (standalone) is installed separately, on a compatible Windows x64/GPU system; Isaac, GPU drivers and API keys are not included. The package is unsigned. Physical robot controls exist only in a development-channel build; the default sim-alpha package is simulation only, and a separately declared read-only robot build can offer explicit connection observations. Check the capability message in Robots.

## Install

1. Get `TwinPulse-Windows-x64-<release version>-<build>.zip` (for example `TwinPulse-Windows-x64-0.1.0-alpha.1-<build>.zip`) and `SHA256SUMS.txt` from the release page or file you were given. Nothing else needs to be downloaded; the PC check is inside the ZIP (see **Check this PC** under [If something fails](#if-something-fails)).
2. Optional: compare the ZIP's SHA-256 with the line in `SHA256SUMS.txt` (case does not matter): `Get-FileHash <zip> -Algorithm SHA256` in PowerShell, or `certutil -hashfile <zip> SHA256` in Command Prompt.
3. Right-click the ZIP → **Properties** → tick **Unblock** if it is shown → **OK**.
4. Right-click the ZIP → **Extract All** to a short, empty folder such as `C:\TP`. The default folder under Downloads makes every path about 13 characters longer than the installed one, and Windows limits paths to 259 characters.
5. Double-click `C:\TP\TwinPulse\Install-TwinPulse.cmd` and wait for the confirmation message. It checks every file and installs for this Windows user under `%LOCALAPPDATA%\TwinPulse\installed`. No network is used.
6. Start with `%LOCALAPPDATA%\TwinPulse\installed\Start-TwinPulse.cmd` (paste it into Win+R, or make your own shortcut; none is created). It starts the installed `TwinPulse.exe` directly; no PowerShell is needed.

Use the `Install-TwinPulse.cmd` inside the extracted `TwinPulse` folder. A source checkout has a file with the same name: that one is the developer install and needs Python, Node.js and package downloads. If Windows or company security still blocks the package, ask IT; do not disable security controls.

**Isaac Sim** is taken from the saved folder when it contains `python.bat`. Otherwise TwinPulse looks in `C:\isaacsim`, `D:\isaacsim\isaac-sim-standalone-6.0.1-windows-x86_64`, `C:\isaacsim\isaac-sim-standalone-6.0.1-windows-x86_64` and `D:\isaacsim`, and takes a folder whose `VERSION` says 6.0.1 before the others. If none of them has `python.bat`, a folder picker asks: choose the folder that contains `python.bat` (a folder without it stops the start with `ISAAC_FOLDER_MISSING_PYTHON_BAT`). When nothing was saved yet, the found folder is saved for later starts; a folder you pick is always saved. A found folder never replaces a saved one: if the saved folder has no `python.bat` at a start (for example on a drive that is not ready yet), that start uses the found folder, keeps the setting and writes a `TWINPULSE_ISAAC_ROOT_FALLBACK` line naming both folders to the launcher log in `%LOCALAPPDATA%\TwinPulse\runtime\desktop-logs`.

**The first start can take up to 10 minutes** while Isaac initializes. The App window opens first and shows the current Isaac phase and the second it started; later starts are usually faster. If Isaac is not ready after 600 s, the message names the last phase.

## Use

1. Wait for the authenticated connection indicator before using 3D commands.
2. Use New chat to create a separate conversation in the same app/address. Run the same installed Start entry to focus/reopen the existing app without another backend or Isaac instance. Portable use of `TwinPulse.exe` from the extracted folder is also supported.
3. Use **Exit TwinPulse** to stop the App and its owned Isaac engine normally. The independent window's close button requests the same normal shutdown; it is not a hide-to-tray action. Stop a simulation or response first if the app asks you to. If only the renderer crashes, the manager does not silently abandon ongoing work: use the same Start entry to reopen it. The explicit diagnostic browser mode is different; closing that browser only closes its view.

## What is checked, and when

| When | What is checked | Your part |
|---|---|---|
| Build PC | Locked build tools and versions, the Burger robot files against their reviewed digests, and that no installed path passes 259 characters | None. Strict, on the builder only: the build stops |
| Download | The ZIP's SHA-256 against `SHA256SUMS.txt` | Optional (step 2) |
| Install | Size and SHA-256 of every file against `windows-release-manifest.json` inside the ZIP, for the extracted folder before any install code runs and again for the installed copy | None. Automatic |
| Each start | Every listed file is present with its recorded size, and no other file was added. Child processes (backend, workers) only read the manifest | None. Quick |
| On demand | The full SHA-256 check of every file | Run `Start-TwinPulse.cmd --inspect-package` (or `TwinPulse.exe --inspect-package` in a package folder), or reinstall |
| Isaac Sim | Its version: any 6.0.1 build is accepted; another version gets a warning, not a block | None |
| SIM robot | The Burger robot files against the digests the build checked; a mismatch names the file. `desktop.ini`, `Thumbs.db` and `.DS_Store` there are ignored; a link is refused, whatever its name | None |

At install and start, `desktop.ini`, `Thumbs.db` and `.DS_Store` are ignored unless the manifest lists them; any other unexpected file stops the check and is named. `--inspect-package` does not start the App. A problem opens a message that names the file and the log with the details in `%LOCALAPPDATA%\TwinPulse\runtime\desktop-logs`; a pass writes `"status": "verified"` to a new log there. SHA-256 identifies bytes; it is not a publisher signature.

## Network

Install uses no network, but AI generation does; `Start-TwinPulse.cmd --offline` is a diagnostic mode that runs local Isaac only and blocks new AI generation. Apart from a robot you connect on the local network, the App contacts only the AI providers you set up, over HTTPS: `api.tokenfactory.nebius.com` (Nebius Token Factory) and, if you route a model to OpenAI, `api.openai.com`. Every request carries the User-Agent `TwinPulse/<product version>`: `TwinPulse/0.1.0a1` for the 0.1.0-alpha.1 ZIP (the ZIP name spells the version differently) and `TwinPulse/dev` from a source checkout. TwinPulse never disguises itself as a browser. If a company filter answers instead of the provider, the App shows the HTTP status and the block page's title, not a key error. When a Nebius key is set up or its model list is refreshed, `provider_blocked_page`, `provider_http_error` and `provider_unreachable` (with a Korean message) tell a filter page, another HTTP error and no connection apart. Ask IT to allow those hosts for User-Agents that start with `TwinPulse/`. Provider calls use the proxy environment variables (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` and the like) when any of them is set, otherwise the proxy server set in Windows Internet Options; a proxy auto-config (PAC) script and automatic proxy detection are not read. TwinPulse listens on 127.0.0.1 only, and calls between its own processes ignore proxy settings. Isaac Sim itself may also try NVIDIA's online extension registry; the extensions TwinPulse needs must already be in the local Isaac install.

## If something fails

- **Install or start stops with `WINDOWS_PACKAGE_FILE_MISMATCH` or `WINDOWS_PACKAGE_UNMANIFESTED_FILE`:** the message names the file. At install, extract the ZIP again into a new, empty short folder and add nothing to it; if it repeats, check the ZIP's SHA-256 (step 2). At start, the installed copy has changed, for example antivirus removed a file or a file was saved into it: if the named file is one you saved there, move it out; otherwise rename that build's folder under `%LOCALAPPDATA%\TwinPulse\installed\releases` (keep it as a record) and run `Install-TwinPulse.cmd` from the extracted folder again. Do not save other files inside the TwinPulse folders.
- **`EXIT_TWINPULSE_BEFORE_INSTALL`:** TwinPulse is running, or `%LOCALAPPDATA%\TwinPulse\runtime\launcher.lock` names a process that still runs and that Windows does not show to be another program. Exit TwinPulse normally; Task Manager → Details should then show no `TwinPulse.exe`. If none is running, restart Windows and install again: a lock whose process has ended is then moved to `runtime\stale-launch-records`. If it still stops while no `TwinPulse.exe` runs, the lock probably comes from an older TwinPulse that did not record when its process started, so a reused process ID cannot be told apart: move `launcher.lock` into `runtime\stale-launch-records` yourself (do not delete it) and install again.
- **`INSTALL_LAUNCHER_LOCK_UNREADABLE`:** that `launcher.lock` cannot be read as a TwinPulse lock (for example an empty file left by a crash). The installer keeps it as it is, and a start stops on it too (`launcher_lock_unreadable` or `launcher_lock_invalid`). With no `TwinPulse.exe` running, move the file into `runtime\stale-launch-records` (do not delete it) and install again.
- **`INSTALL_PATH_TOO_LONG: <n> > 259: <path>`:** installed under your user folder, that package file's path would pass the Windows 259-character limit, and Windows long paths are off. Nothing was copied. Send the message to whoever gave you the ZIP. With long paths turned on by IT (`LongPathsEnabled` = 1) the install continues, but TwinPulse has not been tested with long paths.
- **`engine_path_unsupported`:** Isaac cannot start because a path it needs contains `%` (the message names the folder); `python.bat` cannot pass such a path. Use a Windows account and an Isaac folder whose paths have no `%`. TwinPulse quotes paths that contain `&`, `^`, `(` or `)`.
- **Isaac is not ready after 600 s:** the message names the last phase. Keep `engine.log` from `%LOCALAPPDATA%\TwinPulse\runtime\launches\<launch>`; it keeps its output even when the engine is stopped. If the TwinPulse extension does not start, the App says only that the engine exited (`engine exited with code <n>; see local engine log`). The declared Isaac extensions that are not enabled are listed in the error in `engine-result.json` in the same launch folder, and the PC check report shows the first line of that error; keep both `engine.log` and `engine-result.json`. TwinPulse starts Isaac without the Windows user-site Python folder; do not copy NumPy or SciPy folders into Isaac.
- **A provider error shows a web page title:** a company filter answered; see Network. Provider errors show the HTTP status and a short reason. OpenAI planner requests are checked against OpenAI's strict schema rules before they are sent.
- **Check this PC:** the check is `twinpulse_company_pc_check.py` in the extracted `TwinPulse` folder, next to `Install-TwinPulse.cmd`. Open Command Prompt and run `py -3 C:\TP\TwinPulse\twinpulse_company_pc_check.py` with any Python 3.10+, or `<Isaac folder>\python.bat C:\TP\TwinPulse\twinpulse_company_pc_check.py`. Run it where it is or from a copy outside the TwinPulse folders, and never save other files inside them: the next install or start would stop with `WINDOWS_PACKAGE_UNMANIFESTED_FILE`. It changes nothing and writes one report to your Desktop; without a Desktop folder it writes to the current folder, or to your user folder when the current folder is inside a TwinPulse folder, and `--output-dir <folder>` picks another folder outside them. It never prints keys, prompts or proxy user names and passwords. It names the Isaac folder the EXE will use (the saved one, else a 6.0.1 folder from the usual list first) and runs that folder's `python.bat` twice to see whether numpy or PIL come from your own site-packages folder, which TwinPulse leaves out when it starts Isaac; a run that takes over 90 s is ended with its child processes. By default it sends unauthenticated test requests to `api.tokenfactory.nebius.com` and `api.openai.com` with the Python default and the TwinPulse User-Agent and prints the exact User-Agent it sent; run from the extracted ZIP, that is the ZIP's own version (for example `TwinPulse/0.1.0a1`), the one the App will send. `--no-network` skips them. It also flags a proxy set only by a PAC script, which TwinPulse does not read; `%`, `&`, `^`, `(` or `)` in your user folder path; a leftover `launcher.lock`, judged as the installer judges it (with the code the install would stop with); settings the App would refuse; and Burger robot files that are links, larger than 32 MB or changed. Review the report before sharing it.
- **Anything else:** the message shows the error and its code and names the log file in `%LOCALAPPDATA%\TwinPulse\runtime\desktop-logs`, or says that no log was written. It starts with `TwinPulse could not be installed.` for a failed install, `TwinPulse package check failed.` for a failed `--inspect-package`, and `TwinPulse could not start.` or `TwinPulse could not complete startup.` for a failed start. `TwinPulse.exe --install --quiet` shows no message: it exits with code 1 and writes the log. Also open Diagnostics in the App.

## Moving from an old offline install

For a PC that used the old offline release (`Install-Offline.cmd`, a `releases\tp-<git12>` folder):

1. Exit TwinPulse.
2. Install this ZIP as above. The installer reads the old `active-release.json` with or without a BOM (the offline installer wrote one), keeps a byte-for-byte copy and does not stop on an unreadable old pointer, so nothing needs to be renamed. A leftover `launcher.lock` is moved to `runtime\stale-launch-records` only when its process has ended, or when Windows shows that its process ID now belongs to a process started at another time; any other lock stops the install and is kept (see `EXIT_TWINPULSE_BEFORE_INSTALL` and `INSTALL_LAUNCHER_LOCK_UNREADABLE` under [If something fails](#if-something-fails)).
3. Start from `%LOCALAPPDATA%\TwinPulse\installed\Start-TwinPulse.cmd`. No `--ready-timeout-s` argument is needed.
4. Keep the old launch folders where they are, in `%LOCALAPPDATA%\TwinPulse\runtime\launches`: they are the original failure records, and the PC check reads them there. Do not delete or move them; if you need an archive, copy them. The old `releases\tp-...` folder can stay; it does not conflict.

Projects, settings and API-key references stay in `%LOCALAPPDATA%\TwinPulse\runtime` and Windows Credential Manager.

## Optional automation checks in the same app

Normal Start discards inherited testing-port settings and opens no automation port. For a test session, exit normally and use **Start-TwinPulse-Test.cmd** beside the installed Start (or the portable EXE). It starts the same package with `--automation-test`, a loopback-only port and a visible TEST MODE badge. A running session is never silently changed between normal and test modes; close it normally first. The next normal launch is debug-off.

Open **Tests → Run basic checks** while Isaac is connected and the app is idle. A bundled, version-pinned Playwright worker clicks the actual installed window: Robots, Library typing/results and Twin pane. No extra Node/Chrome installation, paid generation, network discovery or SSH is needed. Do not use the app controls during this short check. **Tests → Open check report** opens the local report and screenshots; these may contain conversation/device information, so review before sharing. Nothing is uploaded automatically. A basic PASS is not full generation, native OS input or physical robot qualification. The debugging port grants local programs broad control of this app; keep testing mode limited to the test session and never expose/forward the port. Robot preparation and motion gates remain unchanged.

API keys holds provider/model routing and editable model-specific harness instructions. Existing saved Legacy routes are not silently rewritten. Save routing explicitly to select a profile; custom/new-model instructions remain compatibility-unverified until tested. Schema, geometry checks and robot authority are not editable through a prompt profile.

Robots starts empty on a fresh installation. Search shows network service advertisements observed during that search, with a last-search time and a maximum 30-second validity (shorter advertisement TTLs expire sooner). It is not a continuous power/reachability or identity check. Saved robots remain registered even when off; no response means not observed, not proven offline. Remembered Bluetooth devices/local ports are separate OS inventory, never current network search results. A robot must advertise a supported service and network discovery must be allowed; simply enabling SSH is not sufficient to appear. Register/select the intended robot explicitly and run Check PC preparation. Search does not automatically connect or change the saved endpoint. Plain SIM builds stop at local preparation. Read-only robot builds additionally offer Check connection: this explicit action runs bounded SSH health reads, existing ROS topic observations and a reviewed board-read check. It does not deploy software, start a sensor driver, collect a survey or enable a motor. Unknown hardware requires an adapter review and calibration; TwinPulse does not infer a safe motor protocol from a Bluetooth or USB name. A successful read-only result is not motion readiness.

The local address is remembered across restarts. If another program occupies that port, TwinPulse selects and remembers a bounded alternative. No public network listener or local DNS configuration is required. Provider API calls are made by the local backend over HTTPS.

Existing API-key references, conversations, scenes and incomplete work remain in `%LOCALAPPDATA%\TwinPulse\runtime`; key material remains in Windows Credential Manager. Moving the extracted package does not move or remove these user records. A different release cannot take control of a live launch from another installation: exit the old launch normally first.

## Manual updates and recovery

Exit TwinPulse normally, extract the entire next ZIP and run its `Install-TwinPulse.cmd`. Installation refuses a live launch; it does not force-stop another instance. It retains the previous executable pointer, rewrites the installed Start entries for the new release and leaves projects, original attachments, incomplete checkpoints, edits and Windows Credential Manager entries in their existing locations. Launch the same installed Start entry afterwards.

Reinstalling the same ZIP checks the installed copy again. If that copy is damaged, the install stops and names the file: exit TwinPulse, rename that build's folder under `%LOCALAPPDATA%\TwinPulse\installed\releases` (keep it as a record) and run `Install-TwinPulse.cmd` again.

This alpha writes data epoch 1 without conversion. A release declaring an incompatible epoch is refused before switching. An interrupted same-epoch install can be rerun from the identical intact package. Do not manually reset data or edit active-release.json. There is no automatic rollback: to go back to an earlier build, run that build's `Install-TwinPulse.cmd`. It installs only when it can read the current data epoch and the capabilities that data requires; otherwise it stops with `DATA_VERSION_REQUIRES_COMPATIBLE_RELEASE` or `DATA_CAPABILITY_REQUIRES_COMPATIBLE_RELEASE` before switching. Data written in a newer format is never converted back for an older build. No automatic update download, forced update, telemetry upload or background paid inference is performed.

For a bug report, open Diagnostics and record App version/build ID, the affected execution ID and your actual click sequence. Export redacted diagnostics only if you want to share them, and review the file yourself. Original prompts, photos, responses and private paths are not required for a public issue. Do not upload keys or a whole runtime directory.
