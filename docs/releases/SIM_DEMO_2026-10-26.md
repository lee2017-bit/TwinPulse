# SIM demo recording — 2026-10-26 (pre-release, virtual robot)

GitHub pre-release: https://github.com/lee2017-bit/TwinPulse/releases/tag/sim-demo-2026-10-26 (asset `twinpulse-sim-demo-2026-10-26.mp4`, 29:37). Frame-by-frame review: `docs/analysis/TWINPULSE_SIM_DEMO_RECORDING_REVIEW_2026-10-26.md`.

**What this is:** a screen recording of the installed TwinPulse App driving a **simulated** TurtleBot3 Burger (Isaac Sim kinematic SIM) through the full chat-to-route loop on a RoomPlan room scan. No physical robot was used; nothing here is a localization, braking or world-registration claim. Labels in the UI stay "operator estimate / not localized".

**Shown, in order (one continuous take, 0:00–10:49, plus three short segments for the photo steps):**
1. Reopen the saved RoomPlan Twin and rebuild it in Isaac with one button.
2. Place a SIM robot by clicking the floor map and dragging its heading (numeric fields stay editable).
3. Connect → Prepare → LiDAR on; LiDAR hit points appear in the Isaac view inside the App.
4. "Survey the room and come back" → the instruction is planned first by **nvidia/nemotron-3-super-120b-a12b via Nebius Token Factory** (one text-only call, ~5 s; shown on the route card), then laid out by the deterministic Path B route planner (observe/survey/return; every safety gate unchanged).
5. Click stops on the route map → the route is re-planned through them ("Operator stops · no model call").
6. Run: per-stop chat messages, a live route card next to the Twin, return to the start.
7. Add a box on the first leg (Twin edit with Engine ACK and Undo) → ask again → a new Nemotron-planned route avoids it → run to completion.
8. Photo analysis (configured observer, deepseek-ai/DeepSeek-V4.1-Flash): a recognized object is placed as a new Twin object (10:49–), then the hand-placed box is replaced by a photo-recognized object in two Twin edits, remove and add (19:08–), which takes the photo crop's dominant colour in Isaac (display only). The Twin edit contract allows one object per edit, so the replacement shows as two COMMITTED edits with Engine ACK.

**Not shown / limitations:** LiDAR-based correction of an existing object's position is implemented but only triggers when real LiDAR disagrees with the Twin (physical runs); SIM LiDAR sees the Twin itself. LiDAR outline boxes come from physical candidates. The straight first leg rule applies when the robot faces clear floor.
