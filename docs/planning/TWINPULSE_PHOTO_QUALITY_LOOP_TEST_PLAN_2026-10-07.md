# 사진 품질·수정 루프 테스트 계획 — 2026-10-07

## 요청과 범위

사용자: “한번에 잘만드는것도 중요하지만 잘못만들었다고 판단하고 다시 수정하는 기능도 중요하거든? 그 루프구조도 잘 되는지 해보자. 총 10회까지 해봐도 돼. 사진과 맞는 방 크기·가구 위치·지지 관계 다 잘 만들었는지 테스트하는 계획부터 세운 후 테스트해봐.”

계획을 먼저 저장한 뒤 기존 제품의 생성/repair 경로를 시험한다. 테스트 목적으로 품질을 검사하는 외부 평가기를 쓰더라도 이것을 제품에 이미 연결된 자동 품질 루프로 주장하지 않는다. 이번은 검증 요청이며 새 관계 compiler/제품 기본정책을 먼저 바꾸어 통과시키지 않는다.

P01 원래 침실 사진만 기존 Nebius Gemma/Nemotron으로 전송한다. 새 호출은 사용자10회 이하이고 공유USD1/60 campaign의 남은7회 이내(시작53/60)로 제한한다. 원본과 실패를 보존하며 원격불명/시간초과는 재시도하지 않는다. 로봇/배포/설치/commit/push/새 에이전트0. 이미지 및 개인 정보는 기존 승인된 사진만, 키/헤더는 출력·저장하지 않는다.

## 실행 순서

1. **저장 actual 음성 대조군:** v320 실제 응답을 exact request/schema/raw와 대조하여 기존 GenerationService로 재사용. 현재 사진과 다른데도 repair0/형식유효로 끝나는지, top_storage/monitor/tabletop_items가 실제로 지지되는지 검사한다. 새모델0.
2. **기존 자동 repair 양성 대조군:** 실제 이전 응답을 바탕으로 region/관측참조 1개를 의도적으로 깨뜨린 통제 입력을 넣는다. 기존 provider/GenerationService의 repair1이 실제 Nemotron에 오류를 전달해 수정하고 재검증하는지 본다. 이것은 ‘모델이 자연발생시킨 첫 실패’가 아닌 fault-injection이며 실제 모델 성공률 분모에 섞지 않는다.
3. **독립 사진 품질 판정:** 원래 사진+후보 geometry/지역 목록을 Gemma에 보내 위치/지지/scale 문제를 구조화하여 받는다. 후보 JSON을 사진처럼 보여주거나 렌더를 보지 않은 모델을 렌더평가로 주장하지 않는다. 모델의 accept가 local 지지검사 FAIL을 덮을 수 없다.
4. **진단→수정→재판정:** 실제 품질 오류를 이전 후보와 함께 Nemotron에 반환해 동일1.1 schema로 수정한다. 기존 제품 내부의 schema repair와 외부 품질-feedback 평가 루프를 명확히 구분한다. 같은 원본/24항목/기존툴/비용한도 유지. compiler의 지지표현 자체가 불가능하면 해당원인을 기록하고 같은 요청을 반복해 비용을 소모하지 않는다.
5. 모든회차 원본/변화/잔여/diagnostic/cost/source SHA를 저장하고 회귀·Baseline/Memory 동기화. 새 후보가 품질까지 통과하면 실제 기존Isaac 경로로 재검증; 품질 FAIL이면 photo-ready/전체demo PASS를 기록하지 않는다.

## 종료 기준

- **성공:** 실제 수정 루프가 계약뿐 아니라 사진의확실한 위치/지지 오류를 찾아 해결하고 재검증; metre scale은 실측이 있어야 별도 PASS.
- **실패:** schema-valid 사진오류를 감지 못함, 정확한feedback 후에도 품질미개선/회귀, 표현계약 불가, 취소/90s/공유repair1/예산한도. 잘못된 장면을 성공으로 표시하지 않는다.
- 최대10회/기존공유남은7회 중 먼저 닿는 한도. 반복으로 해결할 수 없는 compiler 한계 확인 시 일찍 종료한다. 숫자를 채우려고 호출하지 않는다.
