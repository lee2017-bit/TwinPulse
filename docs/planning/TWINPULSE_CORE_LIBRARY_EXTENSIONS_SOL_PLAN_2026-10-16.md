# TwinPulse 핵심 사용자 흐름과 Library 중심 확장 통합 작업지시

작성일: 2026-10-16. 기준 상태: Baseline v1.0.495의 실제 검증 기록. v1.0.496은 이 작업 방향을 기록한 문서 변경이며 제품 완료 판정이 아니다.

이 지시의 목적은 기존 설치 앱의 미완료를 닫고, CAD 없이도 사용할 수 있는 사진·텍스트 기반 Twin을 유지하면서 Library 자산 제작과 선택적 외부 프로그램 연결을 추가하는 것이다. 사용자는 이번에 작업지시 작성을 요청했으며, 문서 작성 자체는 구현·설치·외부 전송·실물 조작 실행이 아니다. 이후 실행 지시를 받으면 아래 순서로 구현과 실제 인수를 진행한다.

## 1 제품 경계

### 환경 생성과 자산 제작

- 환경 생성은 텍스트·공간 사진·텍스트와 사진을 받아 방이나 작업 공간을 구성하는 기능이다. CAD와 외부 확장이 없어도 자체 Library와 제한된 절차형 recipe로 근사 Twin을 만들고 수정·Undo·저장·재열기까지 완료해야 한다.
- Library 자산 제작은 의자·침대·설비·장비 등 개별 자산을 만들거나 가져오는 기능이다. 자체 모델·자연어 기반 recipe 제작을 유지하고, CAD 가져오기와 BRep 제작은 선택적 경로로 추가한다.
- CAD를 환경 사진 분석 API에 보내거나 공간 사진인 것처럼 처리하지 않는다. CAD가 기술적으로 전체 건물이나 조립체를 포함할 수도 있지만, 이번 기본 UX는 Library 가져오기다. 전체 시설 CAD를 분해해 환경으로 만드는 기능은 별도 후속 범위다.
- BRep은 정밀 자산 제작·편집 도구로 취급한다. 사진 해석·상대 배치 문제의 해결책이나 모든 기본 가구 제작의 필수 의존성으로 만들지 않는다.
- 환경 생성기는 등록된 자산을 검색·참조해 배치할 수 있다. 자산 제작 성공과 장면 반영 성공은 별도로 판정한다.
- 외부 CAD·Ansys·PLC 프로그램이 없어도 기존 기본 기능이 작동해야 한다. 외부 구성요소의 권리·라이선스는 변경하지 않으며 TwinPulse Apache-2.0 코드에 일괄 편입하지 않는다.

### 입력 경험

같은 채팅·첨부·진행 카드 패턴을 재사용하되 모든 입력을 같은 처리 파이프라인으로 보내지 않는다.

| 목적 | 예시 | 기본 경로 |
| --- | --- | --- |
| 환경 만들기 | 방 사진, 방 설명 | 환경 관측과 설계 → 자체 자산 또는 Library 참조 → Isaac |
| 환경 수정 | 이 책상을 벽 쪽으로 옮겨줘 | 현재 장면 변경 제안 → 검증 → Apply와 Undo |
| 자산 만들기 | 이 모양의 의자 하나 만들어줘 | Library 자산 작업 → 자체 recipe 또는 선택 BRep → 등록 |
| 자산 가져오기 | 장비 STEP 파일 | Library 가져오기 → 선택 변환기 → 자산 검사와 등록 |
| 자산 배치 | 이 설비를 사진 오른쪽에 놓아줘 | 선택된 자산 버전과 환경 근거 → 배치 변경 → Isaac |
| 분석하기 | 이 CSV의 정지 시간을 계산해줘 | 선택 분석 도구 → 결과 표와 파일, 자동 장면 변경 없음 |

Library에는 기존 기능을 보존한 채 자산 만들기·가져오기·검색·상세·장면에 사용하기를 제공한다. 공통 Attach에서 CAD를 선택하면 첨부 카드에 `Library 자산으로 가져오기` 목적을 표시하고 해당 작업으로 연결한다. 사용자가 명시적으로 요청한 가져오기를 반복 승인시키지는 않는다. 단순 파일 선택만으로 변환·업로드·장면 변경을 시작하지 않는다.

이미지는 `환경 참고 사진`과 `자산 참고 사진` 역할을 구분한다. 역할은 현재 작업 맥락과 명시 지시로 정하고 UI에서 수정할 수 있게 한다. 모호할 때만 짧게 확인한다. 역할·목적·대상 프로젝트가 변경되면 기존 진행 요청을 취소하거나 무효화하고 이전 결과를 새 작업으로 자동 승격하지 않는다.

공간 사진과 장비 CAD를 함께 준 경우도 파일마다 역할을 표시한다. CAD는 Library 처리, 사진은 환경 처리로 나누고, 결과가 준비되면 자산 참조로 합류한다. 초기 공통 첨부가 복수 파일을 지원하지 않는다면 순차 가져오기와 참조 선택으로 같은 사용자 목적을 제공하며 그 범위를 명시한다. 뒤로가기·취소·전환 때 원문과 첨부 초안을 보존한다.

## 3 역할과 실행 운영

- 주 작업자는 GPT-6.1 Sol 매우 높음으로 한다. 설정을 지정할 수 없으면 실제 모델과 추론 설정 또는 확인 불가 사실을 보고한다.
- UI 보조는 GPT-6.1 Sol 높음 1명까지 사용한다. 독립 원인 분석·계약 검토가 필요할 때만 Astra xhigh 검토자를 추가하며 보조는 최대 2명이다. 단순 대기나 문서 요약을 위해 추가하지 않는다.
- 주 작업자가 공통 목적·첨부·작업·자산·장면 계약과 파일 소유를 먼저 정한다. UI 보조는 배정된 React 파일과 UI 검사, 주 작업자는 Python·계약·패키징·실제 통합을 맡는다. 같은 파일을 동시에 수정하지 않는다.
- 실제 Isaac·외부 호출·설치판 교체·유료 시험은 주 작업자만 순서대로 담당한다. 기존 살아 있는 소유 실행을 중복 실행하거나 임의 강제 종료하지 않는다.
- 단계별 구현과 실제 인수가 끝나면 다음 단계로 진행한다. 도구·하드웨어·권한이 막힌 가지는 정확히 남기고 가능한 독립 작업을 계속한다. 미검증 가지를 완료로 바꾸지 않는다.

## 4 공통 계약

### 작업과 첨부

현재 이미지 중심 InputRevision에 CAD를 위장 삽입하지 않는다. 기존 저장본을 읽는 호환성을 유지하면서 목적별 첨부 계약을 확장한다.

- 작업 목적, 첨부 역할, 파일 형식, 원본 SHA, 로컬 보관 참조, 출처와 사용 범위.
- project ID, operation ID, 입력 revision, 기준 장면 revision, 하네스와 도구 버전.
- 준비·대기·실행·취소 요청·완료·실패·결과 불명 상태와 각 상태의 근거.
- 실제 이벤트의 순서와 시각, 진전·수정 대상·대기 원인. 존재하지 않는 세부 진행률을 만들어내지 않는다.
- 중복 호출 방지와 재시도 가능 여부. timeout이 곧 원격 작업 미실행이라는 뜻은 아니며, 결과 불명 작업을 자동 재전송하지 않는다.

### Library와 장면 인스턴스

공통 검색 UI를 사용해도 다음 자산 종류와 편집 능력을 구분한다.

- 자체 파라미터 recipe.
- 가져온 정적 USD 또는 mesh.
- CAD 원본과 변환 산출물.
- 선택적 BRep 원본과 형상 연산 이력.

자산은 ID·불변 버전·원본과 산출물 SHA·제작 도구와 설정·단위·축·치수 근거·지원 면·출처·라이선스·검사 결과를 가진다. visual mesh와 collider는 별도 산출물이다. 원본 CAD 변경, 단순 scale, 배치 변경을 같은 편집으로 표현하지 않는다.

장면 인스턴스는 자산 버전과 transform을 참조한다. 장면 하나의 수정이 Library 원본이나 다른 프로젝트의 인스턴스를 바꾸면 안 된다. 새 자산 버전은 기존 장면에 자동 전파하지 않는다. 자산 참조·지원 관계·충돌 정보도 Undo와 저장 복원에 포함한다.

외부 도구가 없어도 이미 저장된 파생 자산을 표시·배치할 수 있도록 필요한 의존 파일을 프로젝트 또는 관리 저장소에 보존한다. 원본 도구가 필요한 재편집·재변환만 사용 불가로 표시한다. 저장 시 사용자 개인 원본 파일 경로만 참조하고 끝내지 않는다.

### 외부 도구

공통 확장 명세에는 식별자·버전·입출력 schema·설정 화면·실행 어댑터·호환 조건·실행 효과·파일/네트워크 범위·시험 방법·결과 렌더러를 포함한다. 일반 입력창은 기존 UI 구성요소를 우선 재사용하고, 필요할 때만 schema form 라이브러리를 도입한다.

- CLI/Python과 MCP는 같은 공통 작업 계약에 연결되는 선택 어댑터다. 모든 도구가 MCP를 구현할 필요는 없다.
- Python 서비스가 작업과 프로젝트 상태의 권위자다. Electron IPC나 기존 Isaac bridge를 범용 MCP 버스로 교체하지 않는다.
- 도구 실행은 검토된 고정 executable/entrypoint와 구조화된 인자로 한다. LLM 생성 shell/Python을 실행하지 않는다.
- Skills는 작업 지침일 뿐 설치·실행 권한이 아니다. MCP 설명과 행동 속성도 실행 권한의 증거로 신뢰하지 않는다.
- 별도 프로세스·가상환경은 의존성/장애 분리이며 OS 보안 sandbox라고 주장하지 않는다.
- CAD 변환 같은 유한 작업과 PLC/실행 모델의 지속 세션을 구분한다. 지속 세션은 이번에 실제 구현을 약속하지 말고 확장 가능한 경계를 둔다.

결과는 자산 또는 변경 제안으로 반환한다. 형식·경로·크기·의존 파일·출처·단위·축·geometry를 검사한 뒤 Library/장면에 반영한다. 외부 참조·재질·payload 경로의 임의 접근을 허용하지 않는다. 기존 Apply → Isaac ACK → disk commit → current publish와 보상·UNKNOWN 처리·Undo를 재사용한다.

## 5 단계별 작업

### S0 범위와 실패 기준 고정

기존 dirty 변경·원사진·실패 기록·장부·사용자 프로젝트·로봇 선택을 보존한다. 이미 완료된 기능과 재현할 실패를 구분하고, 소스/설치본 SHA와 실제 실행 경로를 기록한다. 아래 인수 표와 비용 장부를 먼저 만들고 시험 결과를 보고 기준을 바꾸지 않는다.

### S1 기존 설치판 오류 해결

request 생성·영속화·조회 순서와 실제404 응답을 재현하고 근본 원인을 수정한다. 단순히404를 무시하지 않는다. Reset 전후 실제 Isaac pose·목표·실행 가능 상태를 확인하고 같은 목표로 다시 시험한다. 다른 목표를 선택해 우회한 결과를 Reset PASS로 세지 않는다.

상태 조회3초 경고와 과거 pending이 현재 작업으로 보이는 문제를 조사한다. New chat/현재 대화 fence, 같은 실행 재사용, 메시지 순서, 정상 종료·재열기를 회귀한다. 과거 안전 이력을 삭제해 현재 상태를 정상처럼 만들지 않는다.

### S2 CAD 없는 기본 생성과 수정 회복

텍스트·사진·혼합 입력이 외부 CAD/BRep 도구 없이 자체 Library와 recipe로 작동해야 한다. 모델 설정은 Flash 관측/Nemotron 설계·수정을 유지한다. 모델별 하네스 편집·저장·snapshot·Legacy 경로를 실제 UI와 실제 생성에 연결해 확인한다. 새 모델 등록으로 기존 프로젝트의 모델·하네스를 자동 변경하지 않는다.

원사진의 주요 가구 상대 위치·장축 방향·지지·누락·중복을 우선 다룬다. 100% 소품 복원이나 실측 없는 절대 치수 정확성을 요구하지 않지만, 주요 배치가 틀린 채 물체 수만 채워 품질 PASS로 만들지 않는다. 치수·불확실성·pending을 보존한다.

실제 실패의 진단이 수정 입력에 전달되는지, 관련 부모·기존 물체의 재배치가 허용되는지, 무변경 응답을 진전으로 세는지, critic의 reasoning 소진과 빈 출력이 어떻게 처리되는지 확인한다. 사진별 좌표 하드코딩·물체 삭제·기하 기준 완화·무한 토큰/재시도 증가는 금지한다. 필요한 모델 응답 계약과 제한된 재개 정책을 수정한다.

구조 관측 → 추정 바닥 → 부모와 중요 물체 우선 최대6개 묶음 → 유효 물체 표시 → 수정 갱신을 실제 이벤트로 보여준다. 임시 작업 바닥은 사진 기반 재구성 완료로 세지 않는다. 마지막 디코드 프레임과 원래 첨부를 유지하고 live/마지막 미리보기/pending을 구분한다. 생성 중 연속 관찰로 깜빡임과 레이아웃 흔들림을 확인한다. Isaac 연결 UI·명령 로그를 유지하며 엔진을 끄지 않는다.

### S3 목적별 입력과 자체 Library 작업

환경 만들기/수정, 자산 만들기/가져오기, 자산 배치의 목적 계약과 UI를 구현한다. 같은 첨부 경험을 재사용하되 작업 대상을 표시한다. CAD를 환경 채팅에 넣어도 원문 보존 후 Library 작업으로 연결하며 사진 API에 전송하지 않는다.

CAD 없이 자연어 또는 자산 참고 사진으로 자체 recipe 자산을 만드는 기존 경로를 재사용한다. 새 자산은 검증 후 Library에 버전 등록하고 원래 작업으로 돌아가 배치한다. Library 등록만 요청한 작업은 현재 환경을 자동 변경하지 않는다. 실제로 지원하지 않는 형상은 한계와 대체 근사를 표시한다.

### S4 로봇과 저장 센서 준비 보완

기존 등록 이름·검색·선택·명시 Check Connection 원칙을 유지한다. 현재 응답, 저장된 장비, OS 기억 목록을 분리하고 미발견을 전원OFF로 단정하지 않는다. 기존 PC 준비 결과를 로봇 인증·센서 정상·주행 가능으로 표시하지 않는다.

로봇 연결 직전까지의 일반 UI, 설정 변경 시 준비 무효화, 저장 센서 가져오기·좌표계/시각/원장면 결속·보정 제안·Apply/Undo를 검증한다. 실제 같은 공간 자료가 없다면 합성 자료의 계약 검사와 실자료 정합 미검증을 분리한다. 다른 방 자료로 정확성을 주장하지 않는다.

CAD의 설계 형상, 사진의 추정 배치, 센서 관측의 위치/거리 근거를 속성별로 보존한다. 센서 보정은 원 CAD 형상을 임의 변형하지 않으며 장면 인스턴스·방 경계의 새 revision을 검증한다. 정지 스캔 하나를 다시점 SLAM이나 모든 가구 신원 확인으로 표현하지 않는다. 실제 연결·수집·주행은 해당 범위의 유효한 승인과 하드웨어 조건이 있을 때만 수행한다. 이번 준비를 실물 전체 인수로 부르지 않는다.

### S5 최소 확장 관리자와 CAD Library 가져오기

확장 및 연결 메뉴에서 설정 저장/프로그램 발견/기능 확인/시험 결과/프로젝트 활성화를 구분한다. 필요한 기능별 사용 가능 상태와 실패 이유를 표시한다. 외부 프로그램을 설치하지 않은 기본 사용자에게 반복 경고하거나 앱 시작을 막지 않는다.

첫 유한 작업 어댑터로 선택 CAD 변환기를 연결한다. 설치 버전·지원 형식·배포 조건을 확인하고 전용 환경에서 실행한다. 초기 지원은 실제 검증한 STEP 등 제한된 형식으로 명시한다. 모든 CAD 형식을 지원한다고 표시하지 않는다. 지원 도구가 없으면 가져오기 가지를 안내 상태로 남기고 자체 Library 기능은 계속 제공한다.

실제 CAD → 로컬 원본 보존 → 변환 → 단위/축/visual/의존 파일 검사 → Library 미리보기·등록 → 버전 고정 참조 배치 → Isaac 확인을 구현한다. 변환 exit0와 파일 존재만으로 성공 판정하지 않는다. 복잡한 형상을 현재 box recipe로 몰래 바꿔 같은 CAD 자산이라고 주장하지 않는다.

외부 CAD 프로그램·변환기의 설치와 라이선스는 별도로 유지한다. 동봉이 필요하면 재배포 조건을 확인한 파일만 포함한다. 변환을 위해 사용자 CAD를 모델 공급자나 다른 클라우드에 자동 업로드하지 않는다. LLM이 필요로 하는 최소 메타데이터/렌더도 기존 전송 범위에 포함되는지 확인한다.

### S6 다른 도구와 MCP 연결로 확장성 검증

CAD와 성격이 다른 실제 분석 도구 하나를 명세·어댑터 추가만으로 등록한다. 예: CSV를 읽고 수치를 계산해 표와 결과 파일을 만드는 로컬 도구. 고정 응답 mock을 쓰지 않는다. 기본 입력·진행·결과 표시를 위해 core와 React를 다시 수정해야 한다면 공통 경계의 결함을 수정한다. 새 종류의 결과 UI가 필요한 경우만 공통 구성요소 추가 이유를 기록한다.

선택 MCP 어댑터도 실제 서버와 기능 목록/입출력/실제 호출/실패/연결 종료를 확인한다. 사용할 수 있는 신뢰된 서버가 없으면 구현·보조 검사와 실제 MCP 인수를 구분한다. 이를 위해 unrelated 프로그램에 쓰기 작업을 하지 않는다. CAD 작업 실행기가 완성됐다는 이유로 MCP까지 완료로 표시하지 않는다.

### S7 선택 BRep 자산 제작

공통 경계를 재사용해 Library의 선택 제작 도구로 연결한다. 검토된 한정 형상 연산과 구조화된 파라미터만 허용하고 임의 모델 생성 Python을 실행하지 않는다. 외부 도구가 없다면 자체 recipe를 계속 제공한다.

작은 실제 자산의 생성·파라미터 변경·버전 등록·장면 배치·Undo·재열기를 확인한다. BRep 원본/visual mesh/collider를 구분하고 성공 코드가 있어도 실제 형상이 바뀌었는지 검사한다. 지원되지 않는 연산·실패는 마지막 유효 자산과 편집 이력을 보존한다. 이 범위는 범용 CAD 편집기나 모든 가구 자동 정밀 제작이 아니다.

### S8 설치판과 사용자 인수 마무리

최종 소스를 동결하고 같은 설치본으로 필수 인수를 다시 수행한다. 일반판은 디버깅 포트가 꺼지고, 명시 Test 진입만 같은 EXE의 로컬 자동화를 허용한다. 새 대화나 도구 실행마다 앱 백엔드/Isaac/브라우저를 중복 띄우지 않는다.

기본 설치판과 선택 도구 구성의 의존성을 분리하고, 버전 호환·자산 보존·업데이트 후 재열기·되돌리기 경로를 확인한다. 새 PC가 없으면 clean-PC 검증은 NOT_RUN이다. 앱과 자산을 포함한 로컬 후보를 준비하되 commit/push/공개 릴리스는 별도 요청 없이 수행하지 않는다.

## 7 권한과 비용

기존 Flash/Nemotron 조합과 유효한 외부 전송 범위를 유지한다. 사용자 최신 Nebius 누적 USD20 승인에 대해 실행 직전 실제 장부를 읽고 사용·held·UNKNOWN·중복 노출을 모두 합산한다. v495의 USD6.9241239는 당시 보호 합계이며 새 작업의 현재 잔액이나 공급자 청구 확정액으로 복사하지 않는다. 이 문서는 새 USD20을 추가하거나 기존 승인을 초기화하지 않는다.

승인된 데이터/목적지/범위는 반복 질문하지 않는다. 문서에 없는 새 개인 CAD의 클라우드 전송, 새 유료 라이선스, 물리 동작, 새 설치 범위 등을 포괄 승인으로 추정하지 않는다. 실제 부족한 범위만 특정하고 그 가지 외의 작업은 계속한다. 설치가 필요한 선택 도구는 기존 설치 재사용을 우선하고, 프로젝트 전용 의존성 설치도 유효한 권한과 라이선스 범위 안에서만 수행한다. OS·전역 Python·Isaac·ROS·드라이버·방화벽을 임의 변경하지 않는다.

제품에 USD1/가격표 만료/작업별 금액 승인창을 되살리지 않는다. 사용자가 신뢰한 확장의 범위와 프로젝트 설정을 저장하되, 새로운 권한이나 외부 전송처로 확대되면 다시 판단한다. 비용/실패/불명 작업의 추적과 제품의 사용량 제한 UI를 혼동하지 않는다.

실물 로봇 동작·유료 Cloud·공개 배포·commit/push는 이 작업의 기본 실행 범위에서 제외한다. 키·자격증명·개인 PC 경로는 공유 확장 패키지에 넣지 않는다. 일반 사용자에게 모든 외부 프로그램 설치를 강제하지 않는다.

## 8 납품과 완료 판정

단계마다 구현/실제 인수/미검증을 구분하고 Baseline·Memory·README·progress·검증 기록을 함께 정리한다. 최종 보고서는 실제 화면이 포함된 하나의 로컬 self-contained HTML로 작성하며 모든 시도·실행 ID·입력/소스/설치/자산 SHA·도구/모델/하네스 버전·시간·실패·비용·정확한 잔여를 포함한다. 키·민감 원자료를 공개 보고서에 넣지 않는다.

완료를 다음 다섯 영역으로 분리한다.

1. CAD 없는 기본 Twin 사용자 여정.
2. 자체 Library 제작과 자산 참조 배치.
3. 선택 CAD/BRep 자산 작업.
4. 외부 도구 확장 계약과 두 번째 도구/MCP 실제 사용.
5. 로봇 연결 준비와 센서 보정 경로. 실물 인수는 별도.

필수 영역이 실패·미검증이면 전체 완료라고 보고하지 않는다. 사용자가 당장 시도할 수 있는 기능과 필요한 외부 프로그램, 아직 시험하지 못한 기능을 명확히 적는다. 시간을 채우기 위한 시험·불필요한 플랫폼 재작성·새 모델 비교는 하지 않는다.

이번에 만들지 않을 것은 확장 스토어, 범용 워크플로 그래프 편집기, 임의 플러그인 UI/AI 생성 코드의 무검토 자동 실행, Ansys 전체 제품군, PLC 실물 폐루프, 전체 시설 CAD 자동 분해기다. 향후 공통 계약에 연결 가능하도록 경계만 유지한다.
