핵심 제품 방향
- 환경 생성과 Library 자산 제작을 구분한다. 가정집은 CAD나 외부 확장 없이도 텍스트·사진·텍스트+사진과 자체 Library/recipe로 근사 Twin을 만들고 수정·Undo·저장·재열기까지 가능해야 한다.
- CAD는 기본적으로 개별 설비·장비·가구의 Library 가져오기 경로다. BRep도 Library의 선택 자산 제작·편집 도구다. CAD를 환경 사진 분석 API에 넣거나 기본 환경 생성의 필수 의존성으로 만들지 마라.
- 채팅·Attach·진행 카드의 사용법은 통일하되 작업 목적을 환경 만들기/수정, 자산 만들기/가져오기, 자산 배치로 구분해라. 이미지도 환경 사진과 자산 참고 사진을 구분한다. 공통 Attach의 CAD는 원문·첨부를 보존하며 Library 가져오기로 연결한다. 단순 첨부만으로 변환·외부 전송·장면 적용을 시작하지 않는다.
- 사용자는 자체 모델만 쓰거나, 선택적으로 외부 프로그램을 연결할 수 있어야 한다. 외부 프로그램의 설치·라이선스는 별도로 유지하고 Apache-2.0으로 일괄 재배포하지 마라.

역할
주 작업자는 GPT-6.1 Sol 매우 높음, UI 보조는 Sol 높음 1명이다. 독립 원인 분석과 계약 검토가 필요할 때만 Astra xhigh를 추가하고 보조는 최대2명이다. 지정 불가 시 실제 설정을 알려라. 공통 상태/API 계약과 파일 소유를 먼저 정해 같은 파일을 동시에 수정하지 마라. 실제 Isaac·외부 호출·설치판 교체·통합시험은 주 작업자가 순서대로 담당한다.

작업 순서
1. v495의 request 조회404, Reset 뒤 같은 목표의 실제 pose/Run 의미, 상태 조회 지연과 과거 pending 표시를 먼저 재현·수정한다. New chat 전환·메시지 순서·중복 시작·정상 종료도 회귀한다.
2. CAD 없는 텍스트·사진·혼합 생성과 실제 자연어 수정/Undo/저장 재열기를 완성한다. 원사진의 주요 배치·방향·지지, 구체적 repair 피드백, 무변경 응답과 critic 출력 소진을 해결한다. 바닥/최대6개 묶음/표시·대기/수정 이유를 실제 이벤트로 보여주고 마지막 유효 화면을 유지한다. 기존 Nemotron 하네스 편집·저장·실제 모델 연결도 검증한다.
3. 목적별 입력과 Library의 자산 만들기/가져오기/검색/상세/장면에 사용하기를 연결한다. 자체 recipe·정적 USD/mesh·CAD/BRep의 편집 능력을 구분한다. 자산 ID와 불변 버전, 출처, 단위/축, 형상·충돌 산출물을 기록하고 장면 인스턴스 수정이 Library 원본이나 다른 프로젝트를 바꾸지 않게 한다.
4. 기존 로봇 검색/등록/선택/명시 Check Connection과 연결 직전 준비를 확인하고 저장 센서의 보정 검토/Apply/Undo를 연결한다. PC 준비를 실제 로봇 연결·센서·주행 PASS로 표시하지 않는다. 같은 공간 실자료가 없으면 실물 정합은 미검증으로 남겨라.
5. 최소 확장 관리자와 공통 작업 실행·결과 검사·로그·취소를 만들고, 첫 선택 CAD 변환기를 Library 가져오기에 연결한다. 실제 CAD 변환·자산 등록·Isaac 참조 배치·Undo·재열기를 검증한다. 도구 미설치/실패가 기본 기능을 막지 않게 해라.
6. 다른 종류의 실제 분석 도구를 명세·어댑터만으로 추가해 공통 UI가 작동하는지 확인하고 선택 MCP 연결도 실제 기능 호출로 검증한다. 이어서 한정된 BRep 자산 생성·변경·Library 등록을 같은 계약으로 구현한다. 범용 CAD 편집기나 확장 스토어까지 만들지 않는다.
7. 최종 설치본을 동결하고 일반 사용자 흐름을 재시험한다. 외부 도구가 없는 기본 구성과 선택 도구 구성을 모두 확인하고 이전 프로젝트·자산·설정의 재열기를 검증한다.

불변 조건
Electron/React와 기존 Python 권위 계층, Isaac 브리지, Apply→ACK→저장→Undo를 재사용한다. MCP로 실시간 엔진/로봇 제어를 대체하지 않는다. 외부 도구는 자산/변경 제안을 반환하고 본체가 검사·반영한다. 역할·프로젝트·입력·revision·도구/하네스 버전을 결속해 취소/전환 후 늦은 결과를 차단한다. 모델이 만든 임의 Python/shell을 실행하지 않는다. 사진별 하드코딩·물체 삭제·기하 기준 완화로 통과시키지 않는다.

실제 시험
일반 설치 Start→실제 Electron New chat/Attach 또는 OS 붙여넣기→Send/Create→생성/수정→저장→종료·재열기를 Computer Use 또는 같은 BrowserWindow의 명시 Test/Playwright로 조작한다. 별도 Chrome, 직접 mutation API, 고정 모델 응답, 내부 상태 주입을 사용자 시험으로 대신하지 마라. 일반 모드와 Test 모드, 실행 도구 Start 호출과 Explorer 더블클릭, DOM 첨부와 OS 붙여넣기를 구분하고 못한 것은 NOT_RUN으로 적어라.
상세 지시의 A01~A17을 사용한다. 최종본에서 ITM0018 원본 동일 bytes 새 생성3회, 텍스트/혼합/미사용 공개 사진2장, 실제 수정·Undo·재열기·취소/재개·repair를 확인한다. CAD 없는 집 생성과 CAD 장비를 Library에 등록한 뒤 공장에 배치하는 여정은 독립 판정한다. 원사진 SHA를 확인하고 다른 사진과 혼동하지 마라. 자동 repair가 실제 없으면 통과로 세지 말고 원 실패의 비파괴 사본 UI 재개 시험을 별도 성적으로 남겨라.

권한과 납품
Flash/Nemotron과 유효한 기존 전송 승인을 유지한다. Nebius 누적 USD20은 새로 추가되는 예산이 아니며 실행 직전 장부에서 이전 사용·미확정·중복 비용을 합산해 지켜라. 승인된 범위를 반복 질문하지 말고 실제로 부족한 범위만 특정해라. 새 개인 CAD 클라우드 전송·새 설치·유료 라이선스 권한을 추정하지 않는다. 제품의 USD1/가격 만료 승인창을 되살리지 않는다. 실물 동작·유료 Cloud·공개 배포·commit/push는 하지 마라.
기존 dirty·원사진·프로젝트·장부·실패 이력을 보존한다. 막힌 가지는 정확히 기록하고 가능한 독립 작업을 계속한다. 실제 화면과 전 시도/실행 ID/SHA/기능·품질·복원·응답성/시간/비용/실패·미검증/정확한 잔여를 하나의 로컬 보고서로 정리해라. 문서와 Memory/Baseline을 동기화하고 일부 성공을 전체 완료로 과장하지 마라.
