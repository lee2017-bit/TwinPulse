  프레임선택, 방향가설 표시, 내보내기는 로봇을 끈 채 검증했다.
- 사진의 위쪽이 창문이라는 사용자 확인은 보존했다. **로봇 전방, 센서0도,
  센서각도 증가방향, 센서→base/world 좌표는 아직 확정하지 않았다.**

- 과거 정지시험의 안정시간 FAIL은 그대로다. 전체 실물 데모 완료가 아니다.

## 다음 세션 순서 — 새 승인 후 담당 에이전트가 실행

[17:36 준비상태 감사](../verification/four-hour-closeout-20260927.md)에 실행 가능한
읽기점검과 아직 구현하지 않은 진단용 주행시험을 구분했다. 기존 일회성
`policy20` 시험은 이미 소모되었으므로 표식을 지우거나 그대로 재실행하지 않는다.
`prepare_robot.py` 기본모드는 배포를 포함하므로 읽기점검 대용으로 사용하지 않는다.
사용자는 로봇OFF·약90분 후 귀가 예정·배터리 약절반 추정이라고 보고했다.
현재 배터리는 UNKNOWN이며 완충 필요나 충전시간을 이 추정만으로 확정하지 않는다.

### A. 전원 ON 이후 읽기전용 점검 1회

사용자가 복귀·전원 상태를 알리고 읽기 점검을 승인하면, 기존
`scripts/check_robot_connection.py`의 `twinpulse-burger` 프로필과
`--board-snapshot --batch` 경로를 사용한다. 확인된 기존 SSH 키 경로만
명시하고 키 내용을 읽거나 출력하지 않는다. 이 문서가 실행 승인은 아니다.

한 보고서에 주소/장치/부팅ID/배포manifest/포트점유/제어프로세스/배터리전압·
전압기반추정잔량/torque/바퀴속도·명령/기존sensor상태를 묶는다. 부팅 후
정해진3분을 무조건 기다리거나 연속 재시도하지 않는다. 응답이 없으면
연결 단계에서 멈추고 전원·네트워크 원인만 구분한다.

| 결과 | 다음 처리 |
| --- | --- |
| 현재 전압/상태 읽기 실패 | UNKNOWN으로 보존. 과거66.1%를 현재잔량으로 쓰지 않음 |
| 충전 필요 기준 또는 보드 보호 | 기존20% 사용자 기준과 독립 보드 보호를 적용. 구동하지 않음 |
| torque ON/포트 점유/예상치 않은 프로세스 | 원인 보고. 자동 OFF/종료/재배포하지 않음; 변경은 해당 범위 승인 필요 |
| 현재 idle 확인·배포 동일 | 기존 배포를 그대로 사용. 설치/전체 빌드를 반복하지 않음 |
| scan/odom 없음·driver 미시작 | 읽기 점검에서의 예상 가능한 상태. 이를 근거로 자동 driver 시작하지 않음 |

### B. 좌표 확인용 정지 센서 세션 — 주행과 별도 승인

- 단순한 방 사진만으로 reflection 포함 후보를 TF로 채택하지 않는다.
- 센서 기준 방향과 실제 로봇 기준 방향을 분리하여 확인해야 한다. 서로
  반대편 일직선이 아닌 **두 개의 식별 가능한 방향 기준**을 확보해야
  회전 오프셋과 좌우 반전을 구분할 수 있다. 정확한 대응이 없으면 후보 유지.
- 관측 구상: 로봇을 움직이지 않은 상태에서 서로 구분되는 두 방향의
  기준물/알려진 면을 기록하고, 설치된 센서/베이스 축의 공식 정의와 대조.
  구체적인 기준물 위치·좌표/각도는 현재 사진에서 임의로 측정하지 않는다.
- 필요 센서 구동은 기존 검증된 bounded capture의 START/시간제한/STOP/
  quiet/포트복원/전후board 결과를 한 묶음으로 기록한다. 실제 회전 정지는
  serial quiet만으로 판정하지 않는다. 정지 세션 중 바퀴 enable/속도명령 없음.
- 기존 저장 자료로 해결되는 분석은 먼저 수행한다. 추가 촬영/수동 측정을
  요청한다면 어느 모호성을 해소하는지와 최소 관찰만 구체적으로 제시한다.

### C. 물리 정지 재검증 / 주행 — 다시 별도 단계

- A/B 통과가 주행 승인을 대신하지 않는다. 기존122ms 안정시간 FAIL의
  원인·검사 코드를 검토하고 기준은 완화하지 않는다.
- 과거8개sample만으로 관성/제어기정착/수신지연 원인을 구분하지 못했다.
  첫zero출력 결과·센서 source/receipt시간·속도/encoder·cleanup을 분리하는
  진단계측은 아직 구현 전이다. 새runner를 PC에서 검증하고 배포승인/현장시험을
  준비하기 전에는 "바로 주행 가능"이라고 안내하지 않는다.
- 실행 준비가 끝난 뒤에만 새 현장 주시 확인과 명시적 제한 주행 승인을
  받는다. 승인 후 장시간 준비하지 말고 즉시 짧은 시험과 종료 보고.
- live sensor 상태는 CLEAR/BLOCKED/UNKNOWN을 분리한다. 한 높이의 라이다로
  가려진 케이블·낮은 물체·단차까지 안전하다고 확정하지 않는다.
- 중단/통신상실/최종정지/torque 상태/독립읽기와 영상·사용자 관찰을 각각
  증거로 기록한 뒤에만 다음 gate를 검토한다.
