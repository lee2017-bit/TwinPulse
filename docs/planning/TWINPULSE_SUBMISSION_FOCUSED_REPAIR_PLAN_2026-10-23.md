## 1. 이번 제출에서 해결할 문제

**실제 공간 데이터를 Twin으로 가져와, 사람이 지시한 변경과 로봇 작업을 검토·시뮬레이션하고, 결과를 다시 열어 확인할 수 있는 한 사이클**을 완성한다. 공장의 환경과 AGV 작업 논리를 계속 갱신하는 비용을 줄인다는 원래 목적을 유지한다. 거실은 접근 가능한 검증 공간이다.

이번에는 제공된 RoomPlan을 초기 기하의 기준으로 삼고, 사진은 의미·누락·임시 물체를 확인하는 보조 근거로 사용한다. 사진만으로 대략 생성하는 기존 기능은 남기되 별도 품질 판정으로 관리한다. RoomPlan 성공을 사진→3D 정확성 해결로 표시하지 않는다.

최종 설명은 다음 정도로 제한한다.

> Import a scanned space, review and revise the Twin, and test robot tasks in simulation with traceable results.

자동 정밀 복원, 실측 수준의 센서 정합, 산업용 자율주행, 완전 오프라인 LLM은 이번 제출의 완료 주장에 넣지 않는다. 실제로 통과한 추가 기능만 설명에 더한다.

## 3. 첫날 4–6시간: 표시보다 먼저 확인할 연결

현재 불확실성은 USD를 읽는 기술 자체보다, 가져온 공간이 기존 상태·편집·제어 경로에서 보존되는지다. 다음 짧은 종단 검증을 먼저 한다. 일반 UI 인수와 개발 진단은 구분해 기록한다.

1. 원 USD→불변 source manifest→안정 object ID→scene revision→Isaac 읽어온 결과까지 연결한다.
2. 가구 하나의 위치 수정→ACK→저장→종료/재열기→Undo가 원 geometry와 연결된다. 기존 tool call 재컴파일이 Import 전체를 지우거나 사각 방으로 바꾸면 실패다.
3. 소파/식탁 의미 ID가 기존 목표 선택기에 실제 등록된다. 원 prim 이름을 보존하는 것만으로는 현재 목표가 만들어지지 않는다.
4. floor 삼각형 영역과 문/벽 geometry를 사용해 이동 가능한 곳과 바깥을 구분한다. 실제 mesh를 사용하는 LiDAR 첫 충돌과 기존 이동 검사에 같은 revision이 전달된다.
5. 명시 취소/프로젝트 전환 후 이전 Import·검사 결과가 늦게 적용되지 않는다.

직접 확인된 수정 경계:

- `scripts/twinpulse_fleet_runtime.py::_navigation_scene`은 현재 Environment world AABB를 읽고, Presentation/RoomModels의 `catalogKind/currentGeometryIds`에서 목표를 만든다. floor는 특정 높이 조건의 가장 큰 사각 bounds를 고른다.
- `sim_fleet_navigation.py`는 사각 bounds/최대128개 AABB 장애물 계약이다. 0.1m grid·0.25m clearance·5m 경로 길이 한도가 있다. 임의 형태 바닥을 이 사각 bounds로만 표현하면 바닥 밖을 통과할 수 있다.
- SceneCompiler/SceneRevision과 수정 ledger는 기존 객체·tool call·fingerprint를 전제로 한다. 별도 USD를 화면에 얹는 것만으로 편집/복원이 완성되지 않는다.

**6시간 판정:** 최소 연결이 성립하면 진행한다. 전체 SceneRevision/편집 엔진 재작성, 새 탐색 엔진, 제어 프로토콜 전면 교체가 필요하면 이번 주의 완전 Import는 중단한다. 검증 가능한 읽기 전용 Import 미리보기와 기존 생성/SIM 여정을 구분해 남기고, 미리보기를 로봇 시험 가능 환경이라고 부르지 않는다. 무관한 다른 목표나 임의 가구 재배치로 통과를 만들지 않는다.

## 4. P0 — 최소 환경 Import

### 4.1 입력 목적과 단위

- 공통 Attach/채팅은 유지하고 `Import space`, `Library asset`, `Reference photo`처럼 짧은 영어 목적을 제공한다. 환경 USD는 Library equipment 하나로 만들지 않는다.
- 우선 제공된 종류의 자체 포함 static `.usd/.usda/.usdc`를 지원한다. 외부 의존, 스크립트/실행, animation, 지원 밖 포맷은 이유와 함께 거절한다. USDZ 등 미구현 포맷을 지원 목록에 내보내지 않는다.
- 원본 bytes/SHA·원 layer/prim·축·단위 provenance를 보관한다. 현재 자료의 Y-up은 명시됐지만 metersPerUnit은 없다. OpenUSD fallback 0.01을 측정값으로 사용하지 않는다. [OpenUSD 단위 계약](https://openusd.org/dev/api/group___usd_geom_linear_units__group.html)
- `Units not set`일 때 사용자 선택 또는 exporter metadata/알려진 길이로 단위를 확정한다. 미터를 선택하면 `User-confirmed units`로 기록한다. 확인 전에도 미리보기는 가능하나 m 단위 이동·실물 정합 준비 완료로 표시하지 않는다. 지금 계획 작성 중에는 단위 답변을 요구하지 않는다.
- Y→Z, 명시 scale, floor 기준 이동을 wrapper transform으로 기록한다. 원 source geometry와 객체 간 상대 변환은 보존한다. 화면상 그럴듯함으로 scale을 자동 확정하지 않는다.

### 4.2 최소 공통 계약

기존 서비스/worker/store를 재사용하고, 필요한 typed 데이터만 추가한다.

| 데이터 | 필요한 정보 |
|---|---|
| Environment source | source ID/SHA/version, 형식, units의 값과 근거, axis, wrapper transform |
| Source object | 안정 ID, 원 prim path, 원 mesh/transform 참조, semantic kind/이름과 근거 |
| Scene override | 객체 ID별 위치/방향 변경, 사용자/모델 제안 근거, 이전 revision |
| Derived geometry | visual/collision/nav/sensor geometry의 생성 정책 버전·동일 source/revision |
| Operation evidence | chat/Twin/project/operation/request/model/harness/source/scene revision·결과/실패 |

이름은 구현 시 기존 타입과 맞춘다. 원 형상은 불변으로 두고 변환 override를 수정한다. 시각 객체를 수정할 때 해당 collision/nav/sensor 캐시를 같은 revision으로 갱신하고, 실패하면 마지막 유효 상태를 유지한다. `/World/TwinPulse` 밖 장면은 건드리지 않는다.

### 4.3 이번 주에 제공할 편집 범위

첫 완료 단위는 **가구 하나의 선택·이름 확인·평행이동·Undo·저장/재열기**다. 임의 방향은 원본에서 보존하되 새 회전 편집은 기존 경로의 재사용이 검증될 때 추가한다. 벽/문 구조 재모델링, 자유 mesh 편집, Library 원형 변경, 관절/물리 파라미터 자동 추정은 포함하지 않는다. 구조물은 읽기 전용으로 유지한다. 적용 가능한 가구 편집은 기존 사용자 조작과 자연어 제안의 공통 typed command로 통과시킨다.

## 5. P0 — 실제 기하를 사용하는 SIM

화면, LiDAR, 충돌, 경로가 서로 다른 방을 가정하지 않게 만든다.

- 원 floor 삼각형/경계 바깥은 이동 불가로 표시한다. 연결된 공간을 전체 사각형으로 채우지 않는다.
- 정적 충돌은 source mesh/검증된 객체별 형상으로 만든다. 방 전체 AABB/convex hull은 금지한다. 회전된 긴 벽의 AABB가 통로를 막는 경우를 실제 geometry로 검사한다.
- 문이라는 이름만으로 통과 가능하게 만들지 않는다. 닫힌 문 mesh와 실제 열린 구멍을 구분한다. 개구부가 없는 자료에서 벽을 임의 제거하지 않는다.
- navigation은 로봇의 수직 점유와 footprint를 반영한 바닥 mask/장애물 투영을 기존 bounded planner에 연결하는 최소 확장을 우선 검토한다. 단일 LiDAR 높이 절단면만으로 전 차체 충돌을 판단하지 않는다.
- LiDAR는 기존 sensor frame/높이·첫 충돌 경로를 재사용한다. RoomPlan 가구가 실제 다리/빈 공간을 생략한 박스라면 센서 결과도 그 단순 모델의 결과다. 이를 실제 가구 정확도라고 하지 않는다.
- 의미 목표는 실제 소파/식탁의 stable object ID에 연결한다. 이동 결과에 목표 ID·원 pose·경로·도착/중단·최종 Stop ACK를 남긴다. 5m 등 기존 한도 밖이면 이유를 표시하고 한도를 임의 확대하지 않는다.
- 경로 막힘/장면 변경 시 중단하고 이유를 보여준다. 화면에서만 도착하거나 목표를 몰래 다른 물체로 바꾸지 않는다.

첫 판정은 **로봇1대가 실제 소파 또는 식탁 중 하나**에 접근하고, 벽·닫힌 경계를 통과하지 않으며, LiDAR ON/OFF·수동/채팅/Stop·가구 이동 전후의 경로/센서 변화를 확인하는 것이다. 첫 시험 전에 기하와 도달 가능성으로 대상·출발점을 정하고 기록한다. 실패 후 다른 목표로 바꾸어 같은 시험의 통과로 세지 않는다. 다른 목표/다중 로봇은 기존 기능 회귀와 추가 시험으로 구분한다. 통로 폭/모델 단순화 때문에 실제로 막혀 있으면 정상 거절이며, “주행 성공”과는 별도다.

## 6. P0 — AI가 의미 있게 하는 작업

RoomPlan Import는 기하 입력이고, TwinPulse의 AI 가치는 장면 이해·변경 제안·작업 지시의 연결이다. 영상에는 실제 Nebius/Nemotron 요청과 적용 결과가 있는 작업을 넣는다.

- 기존 Flash/Nemotron 모델·하네스를 유지한다.
- `Move this chair away from the walkway` 같은 지시는 현재 source 객체 목록/근거를 받아 구체 객체 ID와 변경 제안을 만들고, 실제 geometric 검사→preview→명시 Apply→ACK→revision으로 이어지게 한다. 모호하면 대상을 선택하게 하며 임의 좌표·삭제를 확정하지 않는다.
- 더 좁은 시작점은 선택된 의자를 명시한 거리/방향으로 이동하는 자연어 요청이다. 모델 제안 내용과 적용량을 보여주고 Undo한다. 고정 규칙 parser만 사용한 명령은 Nemotron이 해석했다고 설명하지 않는다.
- `Go near the sofa`가 기존 결정적 parser를 사용하면 그렇게 기록한다. AI가 모든 제어 주기를 처리한다고 홍보하지 않는다.
- 사진2개는 같은 프로젝트의 참고 근거로 보존한다. 현재 단일 이미지 분석 경로를 활용해 사진별로 분석·제안하고, 사진 밖을 빈 공간으로 보거나 원 USD 객체를 삭제하지 않는다. 다중 사진 공동복원은 이번 주의 필수 작업에서 제외한다.
- 원본 사진/사적 평면도를 새 서비스로 보내는 것은 기존 일반 API 예산만으로 승인됐다고 추정하지 않는다. geometry-only 로컬 Import 및 기존 승인 범위의 모델 작업은 독립 진행한다.

## 7. P1 — 사진-only 문제의 제한적 수정

P0 전체 여정이 통과한 뒤 여유가 있을 때만 원인이 확인된 전달 손실 한 가지를 고친다. 이번 제출의 필수 병행 작업은 아니다. P0 연결 검증 실패를 더 많은 모델 호출로 덮지 않는다.

대상은 원 dining trace의 `chairs around table`이 group→individual로 분해되면서 관계를 잃고 모두 한쪽/yaw0으로 배치된 문제다. 원 객체·그룹/부모·table-relative 관계와 불확실을 끝까지 전달하고, compiler가 그 제약을 소비하도록 한다. 개별 위치가 unknown이면 특정 면을 정답으로 꾸미지 않는다. ITM의 support-domain failure는 관계 수정과 별개로 남긴다.

**투입 한도: P0 전체 여정 통과 뒤 반나절.** 앞단 원문 replay로 정보 소실 여부를 확인한 뒤, 같은 원 dining 사진으로 실제 새 생성 전후를 비교한다. 이는 한 사례의 결과다. 사진 기능 전체 개선/완료를 주장하거나 기존6입력 요구를 충족했다고 하려면 변경한 최종 설치에서 원6입력(동일원본3회·혼합·다른사진2개) 재인수가 별도로 필요하다. 시간이 없으면 그 전체 인수는 미완료로 남긴다. 품질은 주요 가구의 상대 배치·방향·지지·누락/중복으로 정하며 단순 충돌/개수/critic consistent로 대신하지 않는다.

한도 내 효과가 없거나 P0를 방해하면 해당 변경은 제출 후보에서 제외하고 기존 경로를 `Approximate draft`로 남긴다. 과거 실패0/6과 새 결과를 분리한다. 임의 방 형상·연속 pose schema의 전면 교체, DA3/VGGT/COLMAP 여러 모델 도입, 대규모 학습은 제출 후로 미룬다.

## 9. 실물 로봇 시험의 위치

실물 목표는 별도 트랙으로 유지한다. 소프트웨어 핵심 경로가 준비되면 10/26–27 중 가능한 한 번의 감독 세션에 연결/Prepare/readback→정지 sensor/전압→수동·채팅→scan/Stop→로그 반출을 묶는다. 로봇이 꺼져 있어도 가능한 준비/저장자료 분석은 먼저 한다. 실제 감독 가능 시간이 없으면 실물 완료를 약속하지 않는다.

RoomPlan 원점과 실제 odom/frame은 자동으로 같지 않다. 같은 공간 정합이 없으면 물리 `Go near sofa`까지 확대하지 않고 준비된 상대 이동/정지·센서 증거로 판정한다. 실물 움직임은 exact operation의 명령/readback·odom·정지 노이즈 대비 scan을 함께 보며, 바이트가 변했다는 이유만으로 성공이라 하지 않는다.

연결/정지 증거가 부족하거나 새 차단 오류가 생기면 해당 세션의 이동은 중단하고 원 실행 ID로 분석한다. 실제 수정이 필요하면 후보를 다시 동결/회귀한다. 제출 직전에 로봇 전원을 반복 요청하는 무제한 수정·재시험은 하지 않는다. 충분한 실물 증거/영상이 없으면 제출 설명과 트랙 적합성을 다시 판단한다.

## 10. 공개·영상 준비는 첫날부터 병행

현재 private 저장소에는 개인 경로·사적 분석 문서 등이 있으므로 단순 public 토글을 예정하지 않는다. 기존 비공개 이력은 보존하고, 검토한 source commit으로부터 공개할 파일/예제/문서/notice의 정확 목록과 SHA를 먼저 만든다. 역사 전체 공개 검수보다 안전하고 빠르면 **별도 정제된 공개 제출 snapshot**을 제안한다. 실제 외부 공개는 그 구체 후보와 기존 사용자 승인 범위에 맞춰 진행한다.

필수 항목:

- 공개 가능한 코드·라이선스/third-party notice·의존성·버전·빌드/실행 안내.
- 개인 집 원사진/USD·센서 원문·계정/키·장치주소·비공개 Downloads 원문은 공개 후보에서 제외. 사용자 집 영상은 공개할 화면 범위를 별도로 확정한다.
- 작은 자작/권리확인 예제로 재현 가능한 Import/SIM 제공. 사용자 공간 성능의 증거와 자작 fixture 시험은 구분한다.
- 기존 `docs/RELEASE_PROVENANCE.md`의 파일별 검수를 해결한다. 지금의 public-review gate가 로컬 빌드 PASS만으로 자동 통과하지 않는 점을 작업량에 포함한다.
- README: 원문제, 현재 가능한 기능/한계, Windows/Isaac 전제, Nebius/Nemotron 실제 역할, 실행순서, 로그 ID 확인법, Codex/Claude Code가 명시 Test BrowserWindow를 조작하는 방법.
- source commit·설치 manifest·예제/영상·실제 API 실행을 한 제출 manifest로 연결한다. 영상 때문에 여러 Release를 만들지 않고 최종 후보1개·영상1개를 기본으로 한다.

권장 영상은 약2분30초다. 실제 핵심 여정을 보여주고, 생성 대기는 배속 표시로 줄인다. SIM 중심이면 문제→새 프로젝트/입력→Import/AI 변경→로봇 등록/조종→scan/Stop→Undo/재열기를 연결한다. Physical AI에 실물을 포함하면 위 길이 안에 필요한 실제 하드웨어 클립 시간을 먼저 확보하고 SIM 설명을 줄인다. 공개 전 공식 영상 조건을 재확인한다.

커서는 실제 pointer-event annotation을 사용하고, 명령 입력 뒤 약3초 읽을 시간을 준다. 마커/패널이 로봇을 가리지 않아야 한다. 촬영 후 전체 decode와 처음/끝·핵심 프레임을 확인하고, SIM/배속/추정/실물의 구분을 화면에 표시한다. 저장 장면 조종 영상을 새 생성 데모라고 부르지 않는다.

## 11. 역할·비용·보관

구현 착수 시 main이 공통 데이터 계약과 파일 소유부터 정한다. UI 보조1명은 Attach/단위/상태/compact controls만, 독립 Astra 검토1명은 첫날 연결과 최종 증거를 읽기 검토한다. 동일 파일 동시 수정은 피한다. 실제 Isaac/설치 교체/외부 모델 요청/통합시험은 main이 순차 진행한다.

이번 계획은 실제로 main이 작성하고 **GPT-6 Astra xhigh 읽기 전용 계획 검토**를 받았다. 검토 결과인 첫날 계약 연결 판정, 한 로봇·한 대상·한 편집, 사진 수정 반나절 조건부, 공개 검수 선행을 반영했다. 구현·인수 완료를 의미하지 않는다. 후속 구현에서 사용할 모델/effort를 지정하지 못하면 실제 설정을 먼저 밝힌다.

현재 장부상 추가 USD50 잔여는45.3100070이고, 별도 옛 USD20 장부와 GPU Compute 약USD100 진술을 합치지 않는다. 착수 전 실제 장부를 재확인한다. 모델 호출은 고정된 소규모 비교표로 시행하고 미확정/중복 비용도 포함한다. 이번 계획은 새 Cloud/GPU/SDK 설치나 집 자료의 새 외부 전송을 실행하지 않는다.

빌드는 현재 정상 롤백1개·후보1개·정확히 필요한 재현본만 유지하는 원칙을 쓴다. raw/project/사진/장부는 별도 보존한다. 새 full build 전 실제 disk/RAM를 측정하고, 정리 필요 시 기존 승인된 경로와 정확 inventory에 한정한다.
