Computer Use/실제 브라우저 클릭을 사용해라. 제품 API 직접 호출, 고정 응답, 저장 결과 재사용, 내부 상태 주입을 실제 사용자 시험으로 대신하지 마라. 실행 도구로 동일 Start 파일을 호출해야 하거나 native Isaac/OS 붙여넣기를 시험할 수 없으면 그 차이를 NOT_RUN과 함께 정확히 밝혀라.

동결된 최종본에서 같은 원사진 새 생성3회, 텍스트, 텍스트+사진, 미사용 다른 사진2장, 실제 자연어 수정/Undo/저장 재열기, 생성 취소·재개를 계획서 시험표대로 진행해라. OS 붙여넣기의 전송 bytes가 달라지면 동일 바이트 반복과 분리해라. 생성 중 화면도 연속 관찰해라. 물체 수가 찼다는 것만으로 사진 품질 PASS를 주지 말고 주요 가구의 위치·방향·지지·누락·중복을 원사진과 비교해라. 실측 없는 치수는 추정으로 남겨라. 자동 repair가 실제 발생하지 않았다면 그 분기를 통과했다고 하지 마라.

빠른 초기 구조와 상세 관측이 달라질 때도 물체 중복/유실 없이 새 revision으로 재검증·재배치해라. fresh 시험에서 repair가 발생하지 않으면 핵심 수정 회복은 미검증으로 남기고, 승인 범위 안에서 원 실패 체크포인트의 비파괴 사본을 UI로 재개하는 실제 모델 보조 시험을 검토해라. 이를 fresh 새 생성 성적에 합치지 마라.

Flash/Nemotron 조합을 유지해라. 실행 시 유효한 기존 외부 전송 승인과 누적 잔여 예산을 확인하고, 중복 실행·미확정 비용도 포함해 지켜라. 승인된 범위는 반복 질문하지 말고, 실제 부족하거나 만료된 범위만 구체적으로 보고해라. 앱의 금액/가격 승인창을 되살리지 마라. 실물 로봇·유료 Cloud·새 설치·공개 배포·commit/push는 하지 마라. 기존 dirty 변경·원사진·사용자 프로젝트·실패 이력을 보존해라.
